# Research Landscape 순차 개발 프롬프트

작성 기준: 2026-10-14. 기존 장문 기획과 사용자가 첨부한 평가를 통합한 실행용 수정안입니다. 앱 구현이 아니라 개발 에이전트에 순서대로 전달할 프롬프트입니다.

## 사용법

1. 대상 프로젝트를 개발 도구에서 엽니다.
2. 01-prompt.txt 전체를 복사해 입력합니다. 기존 장문 프롬프트를 다시 넣을 필요는 없습니다.
3. 에이전트가 해당 단계 구현·검증·기록을 마치면 02, 03 순서로 한 파일씩 입력합니다. 한꺼번에 넣지 않습니다.
4. 단계가 실패했다면 같은 대화에서 실패 항목을 먼저 수정한 후 다음 번호를 넣습니다. 외부 키 부재는 별도의 ‘실제 연동 미검증’으로 기록하며 가능한 독립 구현은 이어갈 수 있습니다.
5. 새 대화로 옮겨도 같은 저장소를 열면 각 프롬프트가 docs의 계약·진행 기록을 먼저 읽습니다. 같은 저장소에 기록 파일이 없다면 1번부터 시작합니다.

기본 결정은 이 수정안의 제안입니다: HTML/CSS/JS 유지 + Express 서버, 클라우드는 Supabase, AI는 OpenAI Responses API. 1번에서 이를 문서에 고정하므로 실행 에이전트가 매 단계 기술을 다시 고르지 않습니다. 기술 구성을 바꾸려면 1번 실행 전에 해당 결정을 함께 수정하세요.

## 범위 경계

- 1~7번: 핵심 기능을 실제로 클릭·편집·저장·내보낼 수 있는 예시 제품. 진짜 검색·AI·계정 연동 완료를 뜻하지 않습니다.
- 8~11번: 실제 검색·인증·저장·AI·피드백. Supabase 설정과 API 자격 증명이 필요합니다. 비밀키는 채팅에 붙이지 않고 환경 설정에 넣도록 안내합니다.
- 12~14번: 권한 있는 PDF, 조건 비교, 인쇄, 실패 복구·보안·접근성 검증. 실논문 3편이 없으면 합성 자료 테스트와 실논문 검증을 구분합니다.
- 전체 묶음은 원래 범위를 모두 배치하되, 제외/후속 기능은 삭제하지 않고 명시적인 후속 목록으로 보존합니다.
