Research Landscape — 14/14 전체 인수 검증과 개발 인계

[이전 단계 이어받기]
먼저 AGENTS.md와 docs/PRODUCT_CONTRACT.md, docs/PROGRESS.md, docs/DECISIONS.md, docs/TEST_MATRIX.md를 읽어라. 계약 파일이 없다면 1번이 아직 적용되지 않은 것이므로 전제를 추측하지 말고 필요한 1단계 기록부터 복원하라. 기존 사용자 변경과 작동 기능을 보존하라.
지정된 이번 단계만 구현·검증하고 다음 번호를 자동 실행하지 마라. 선행 결손은 이번 작업에 필요한 범위에서 먼저 수정하라. 키·계정이 없으면 독립 구현과 고정 응답 테스트를 진행하되 실제 연동은 미검증으로 남겨라. 보안이나 데이터 무결성 전제는 우회하지 마라.

14/14단계: 새 기능을 늘리지 말고 전체 요구사항의 누락·오류를 수정하고 인계하라.

[누락 점검]
제품 목표와 두 화면 구조, 친근한 입력, 범위 조정, 한국어/영어 검색어, 연구 갈래, 논문 역할·읽을 이유·위치, 연구실 선택 입력, 방향 근거·불확실성, 비교·Claim·원문 패널, 저장·삭제·버전·피드백, 복사/Markdown/인쇄를 실제 코드와 대조한다.
모드 분리, 가상 예시 명시, 초록 전용 위치 미생성, 동향 집계 조건, 수치/단위/조건, 사용자 확인 해제, AI 전송 동의, 예산, 캐시, 인증/RLS, 업로드·만료·삭제, 오래된 응답·부분 실패·worker 복구도 포함한다.
기능이 누락되면 관련 범위 안에서 구현·수정한다. 테스트가 없다는 이유로 기존 기능을 완료 처리하지 않는다.

[인수 시나리오]
1. 키 없는 예시 전체 흐름: 입력 → 수정 → 선택 → 준비 → 저장/복원 → 내보내기 → 삭제.
2. 실검색·AI·DB 전체 흐름: 로그인 → 실제 검색 → 동의 → 분석 → 방향/논문 선택 → 준비 → 저장 → 피드백 버전.
3. PDF·비교: 권한 있는 3편 → 업로드/추출 → 근거 위치 → 조건 비교 → 수정 → 인쇄 → 파일 삭제.
4. 실패: 0건/429/초록 없음/원문 없음/PDF 실패/AI 실패/부분 성공/저장·내보내기 실패/예산 초과.
5. 보안: 타 사용자 데이터 접근, 비공개 파일 URL, 미동의 전송, 로그의 민감정보, URL 다운로드.
6. UI: 1280px, 375px, 실제 200% 확대, 키보드, 포커스, 대비, reduced-motion.

[검증·보고]
실제 존재하는 check/test/e2e 명령을 실행한다. 정적 프런트엔드는 빌드가 없을 수 있으므로 존재하지 않는 빌드를 통과했다고 쓰지 않는다.
검증표의 각 행은 ‘실제로 확인 / 고정 응답으로 확인 / 실패 / 외부 조건으로 미검증’ 중 하나로 기록한다. 실제 인증·검색·AI·PDF·삭제는 따로 판정한다.
예시 라벨은 화면·근거 패널·다운로드·인쇄에 존재하는지 자동/시각 검사한다. 오류 화면은 설명과 실행 가능한 다음 행동이 있는지 확인한다.
실제 브라우저 확대를 못 하면 그 사실을 남긴다. 테스트 실행 불가도 통과로 바꾸지 않는다.
외부 설정이 없으면 이를 필요 조건으로 기록하고 실제 서비스 출시 가능이라고 표현하지 않는다.

[문서·인계]
README에 Windows 실행법, 설정 순서, 환경변수 이름/역할, 서버/worker 실행, 마이그레이션, 삭제 정리 작업, 예시와 실제 모드, 문제 해결을 정리한다.
docs/ACCEPTANCE.md에 결과·캡처·검증 자료 출처·남은 위험을 기록한다. PRODUCT_CONTRACT/PROGRESS/DECISIONS/TEST_MATRIX/BACKLOG를 최종 코드와 맞춘다.
공개 배포는 이번 단계에서 자동 실행하지 않는다. 배포가 필요한 경우 실행 가능한 배포 절차와 환경 조건까지만 제공한다.

[제품 검증과 후속]
실제 랩 한 곳·주제 하나에서 연구 방향 2개 이상을 근거로 설명할 수 있는지, 준비 시간이 줄었는지, 교수 피드백 후 다시 사용하는지 측정할 짧은 사용자 검증안을 만든다. 20~30분 탐색 이해 목표는 가설이며 실측 성과라고 쓰지 않는다.
후속 목록: citation graph, 범용 공정 추출, 연구자/기관 분석, 새 논문 알림, 장기 동향, 결제/구독, 다른 이공계 분야. 카드보다 판단에 도움이 되는지와 반복 사용 근거를 확보한 뒤 진행한다.
상품 가설: 무료 탐색, 유료 ‘랩미팅 근거 정리’. 가격·사용량·과제 단위/구독 선택은 아직 검증 대상이다.

[최종 답변]
실행 방법, 완성 범위, 실제 연결된 서비스, 검증 결과, 외부 미검증/남은 과제만 짧게 전달하라. P0/P1/P2의 완료 수준을 각각 밝히고 전체 완료와 일부 완료를 혼동하지 말라.

[단계 종료]
이번 변경, 검사 결과, 미완료·외부 미검증, 필요한 설정, 다음 번호를 docs/PROGRESS.md에 갱신하고 결정이 달라졌으면 docs/DECISIONS.md에 근거를 남겨라. 수행하지 않은 검사·연동·저장을 완료라고 보고하지 마라. 필수 조건이 실패하면 다음 입력 전에 해결할 항목을 밝혀라. 최종 답변은 구현 결과·확인 결과·남은 항목·다음 번호만 간결하게 작성하라.
