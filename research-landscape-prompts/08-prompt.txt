Research Landscape — 08/14 서버·인증·클라우드 저장

[이전 단계 이어받기]
먼저 AGENTS.md와 docs/PRODUCT_CONTRACT.md, docs/PROGRESS.md, docs/DECISIONS.md, docs/TEST_MATRIX.md를 읽어라. 계약 파일이 없다면 1번이 아직 적용되지 않은 것이므로 전제를 추측하지 말고 필요한 1단계 기록부터 복원하라. 기존 사용자 변경과 작동 기능을 보존하라.
지정된 이번 단계만 구현·검증하고 다음 번호를 자동 실행하지 마라. 선행 결손은 이번 작업에 필요한 범위에서 먼저 수정하라. 키·계정이 없으면 독립 구현과 고정 응답 테스트를 진행하되 실제 연동은 미검증으로 남겨라. 보안이나 데이터 무결성 전제는 우회하지 마라.

8/14단계: P0 기록을 확인한 뒤 서버·계정·저장을 연결하라.

[서버]
Node.js + Express ESM 서버를 추가하고 기존 정적 UI와 /api를 같은 출처로 제공한다. 로컬 개발 스크립트는 Windows에서도 작동하게 한다.
서버는 허용한 정적 경로만 제공하며 .env·문서 원본·저장 파일을 정적으로 노출하지 않는다. 입력 검증, 요청 크기 제한, 안전한 오류 형식, 요청 ID를 구현한다.

[설정]
.env.example에 SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, OPENAI_API_KEY, OPENAI_MODEL=gpt-5.4-mini, SEMANTIC_SCHOLAR_API_KEY, CROSSREF_MAILTO, APP_ORIGIN, PORT를 명시한다.
공개 가능한 Supabase URL/anon 키와 서버 전용 비밀키를 구분한다. 값이나 토큰은 로그·보고서에 출력하지 않는다.
새 클라우드 프로젝트 생성, 유료 플랜 전환, 공개 배포는 자동 실행하지 않는다. 계정이 없으면 마이그레이션·어댑터·연결 안내·고정 응답 검증을 완성한다.

[인증과 접근 제어]
Supabase Auth 이메일/비밀번호 가입·로그인·로그아웃·비밀번호 재설정을 연결한다. 이메일 확인 대기와 실제 실패를 구분한다.
인증 설정이 없으면 로그인 메뉴를 숨기고 예시 모드만 제공한다. 익명 세션 ID를 인증 대용으로 서버에서 신뢰하지 않는다.
서버는 매 요청의 토큰을 검증한다. 프로젝트 소유자는 요청 본문의 userId가 아닌 검증된 사용자로 정한다.
PostgreSQL 테이블·마이그레이션·RLS를 작성한다. 일반 사용자 요청은 사용자 토큰으로 RLS를 적용하고 service-role은 제한된 내부 작업에서만 사용한다.
프로젝트 저장/조회/목록/이름 변경/삭제를 실제 DB에 연결한다. 여러 탭의 충돌은 revision으로 감지하고 마지막 저장이 조용히 덮어쓰지 않게 한다.
로컬 예시를 클라우드로 자동 업로드하지 않는다. 사용자가 선택한 프로젝트만 명시적인 가져오기로 이동한다.

[데이터 처리]
연구실 정보의 클라우드 저장 위치와 범위를 알려준다. 외부 AI 전송 동의는 별개이며 10단계에서 구현한다.
소유자가 프로젝트 삭제를 하면 관련 데이터와 이후 파일/작업까지 정리할 계약을 만든다. 삭제 중/실패/완료를 구분한다.

[완료 기준]
인증 누락, 만료 토큰, A 사용자의 B 프로젝트 읽기/쓰기/삭제 차단, 충돌 저장, 로그아웃 후 접근 차단을 테스트한다. 실제 Supabase 검증은 서로 다른 테스트 사용자로 수행하고, 계정이 없으면 ‘고정 응답 테스트 통과·실제 인증/DB 미검증’으로 남긴다. 접근 제어를 끄는 우회는 금지한다.

[단계 종료]
이번 변경, 검사 결과, 미완료·외부 미검증, 필요한 설정, 다음 번호를 docs/PROGRESS.md에 갱신하고 결정이 달라졌으면 docs/DECISIONS.md에 근거를 남겨라. 수행하지 않은 검사·연동·저장을 완료라고 보고하지 마라. 필수 조건이 실패하면 다음 입력 전에 해결할 항목을 밝혀라. 최종 답변은 구현 결과·확인 결과·남은 항목·다음 번호만 간결하게 작성하라.
