Research Landscape — 06/14 랩미팅 준비와 주장·근거 편집

[이전 단계 이어받기]
먼저 AGENTS.md와 docs/PRODUCT_CONTRACT.md, docs/PROGRESS.md, docs/DECISIONS.md, docs/TEST_MATRIX.md를 읽어라. 계약 파일이 없다면 1번이 아직 적용되지 않은 것이므로 전제를 추측하지 말고 필요한 1단계 기록부터 복원하라. 기존 사용자 변경과 작동 기능을 보존하라.
지정된 이번 단계만 구현·검증하고 다음 번호를 자동 실행하지 마라. 선행 결손은 이번 작업에 필요한 범위에서 먼저 수정하라. 키·계정이 없으면 독립 구현과 고정 응답 테스트를 진행하되 실제 연동은 미검증으로 남겨라. 보안이나 데이터 무결성 전제는 우회하지 마라.

6/14단계: 두 번째 작업 화면 ‘랩미팅 준비’를 구현하라.

[화면]
조사 질문·범위, 선택한 방향과 논문, 비교 정보, 발표할 문장·근거, 확인할 사항, 내보내기 영역을 한 화면에 둔다. 새 필수 마법사 단계를 만들지 않는다.

[논문 비교]
공통 항목은 연구 목적, 접근법, 재료·공정, 주요 결과, 적용 조건, 저자 한계, 이번 조사와의 연결.
수치에는 단위·측정 조건·Evidence를 연결한다. 조건이 다르면 직접 비교하기 어려운 이유를 표시한다.
네 가지 빈값 이유를 사용하고 추정으로 채우지 않는다. AI/예시의 원래 값과 사용자 수정값·시각·출처를 보존한다.
원문 기반 자동 공정 추출은 아직 구현하지 않고, 계약과 예시·수동 편집을 연결한다.

[주장 편집]
Claim 카드마다 말할 내용, 논문 근거, 적용 조건, 사용자 해석, 추가 확인을 제공한다.
근거 패널에는 발췌·페이지/절/그림/표·자료 범위·원문 링크를 표시한다. 좌표가 없으면 해당 항목은 숨기고 위치 안내만 한다.
P0의 근거는 예시 문서라는 표시를 유지한다.
문장 수정 시 기존 Evidence 연결은 보존하되 사용자 확인을 해제하고 ‘추가 확인 필요’로 되돌린다. ‘근거 다시 확인’을 제공한다. 자동으로 재검증 완료를 선언하지 않는다.
요약과 해석 가까이에 ‘AI 해석이 포함되어 있어요. 발표에 사용할 조건과 수치는 연결된 원문에서 확인하세요.’를 표시한다. 예시에서는 실제 AI 실행 여부도 구분한다.

[상호작용]
자동 질문 팝업은 사용하지 않는다. 사용자가 Claim의 ‘근거 함께 살펴보기’를 누르면 한 번에 질문 하나만 제시한다.
우선순위: 근거 없음 → 적용 조건 없음 → 연구실 적용 주장인데 정보 없음.
세 가지 행동: 주장 범위 수정 / 근거 추가 / 교수님께 확인할 질문으로 남기기.
‘모르겠어요/원문에서 못 찾았어요’를 정상적으로 처리한다. 이해도·자신감·준비 완료 점수는 만들지 않는다.

[완료 기준]
탐색 선택과 준비 화면 일치, 근거 패널 열기/닫기·포커스 복귀, 문장 수정 시 확인 상태 해제, 비교 셀 수정 이력, 미확인 유지, 조사 화면 복귀 시 상태 보존을 테스트한다.

[단계 종료]
이번 변경, 검사 결과, 미완료·외부 미검증, 필요한 설정, 다음 번호를 docs/PROGRESS.md에 갱신하고 결정이 달라졌으면 docs/DECISIONS.md에 근거를 남겨라. 수행하지 않은 검사·연동·저장을 완료라고 보고하지 마라. 필수 조건이 실패하면 다음 입력 전에 해결할 항목을 밝혀라. 최종 답변은 구현 결과·확인 결과·남은 항목·다음 번호만 간결하게 작성하라.
