3/14단계: 공통 디자인과 랜딩을 구현하라.

[디자인]
전 화면에 다음 CSS 토큰을 적용한다: 배경 #F7F9F8, 카드 #FFFFFF, 본문 #172B35, 보조 글자 #586873, 강조/링크 #066873, 옅은 강조 #EAF5F4, 구분선 #DCE5E4, 확인 필요 #8A5A16.
#087F8C를 옅은 배경 위 작은 본문에 쓰던 조합은 사용하지 않는다. 실제 렌더된 색 조합으로 일반 글자 4.5:1, 큰 글자 3:1, 필수 UI 경계/포커스 3:1을 확인한다.
헤더 약 64px, 최대 폭 1240px, 본문 16px/1.6, 모서리 10~12px, 간격 8px 단위. 기존 한글/영문 폰트는 활용하되 외부 폰트 실패 시 시스템 폰트로 읽히게 한다.
얇은 구분선·여백 중심의 학술 도구 분위기, 과한 그림자·장식용 그래프·허위 통계는 제외한다.

[랜딩]
- 브랜드·페이지 제목·접근성 이름·파비콘을 Research Landscape에 맞춰 일관되게 변경한다.
- 헤더: 사용 예시, 저장한 조사. P0에서 로그인은 숨긴다.
- 헤드라인: ‘교수님이 주신 주제, 어떤 논문부터 읽어야 할까요?’
- 설명: ‘먼저 읽을 논문과 이유를 찾고, 우리 연구실과의 연결점과 랩미팅에 필요한 근거를 정리하세요.’
- 입력 라벨: ‘어떤 연구를 알아보고 있나요?’
- 안내: ‘교수님이 하신 말이나 궁금한 주제를 편하게 적어주세요.’
- CTA: ‘읽을 논문 찾기’, 보조: ‘예시로 살펴보기’.
- EUV PR·ALD·HBM 예시 버튼은 입력을 채우고, 사용자가 수정한 뒤 실행할 수 있게 한다.
- 히어로는 읽을 부분 → 읽는 이유 → 랩미팅 활용을 연결한 기능 예시다. ‘실험 조건 / 한계’ 전환 시 발췌 강조와 설명을 함께 바꾼다.
- 예시는 ‘가상 예시 · 실제 논문 아님’을 가까이에 항상 표시한다.
- 임의의 자유 입력을 고정 예시로 처리할 때는 실제 검색이라고 표현하지 않는다. ‘이 주제의 실검색은 아직 연결되지 않았어요’와 선택 가능한 반도체 예시를 제공한다.
- 기존 이용 방법·근거 처리 설명을 짧게 정리한다. 요금 섹션은 FAQ로 통합하고 실제 지원 범위를 설명한다. 후속 유료 가설은 PRODUCT_CONTRACT에 보존한다.

[공통 접근성]
키보드·포커스·본문 바로가기·폼 라벨·reduced-motion, 텍스트+아이콘 상태 표시. 375px 화면과 200% 확대에서 입력/버튼이 겹치지 않게 한다.
저장한 조사는 빈 상태를 먼저 제공하고 7단계에서 연결한다. 미구현 버튼을 작동하는 듯 표시하지 않는다.

[완료 기준]
랜딩 입력·예시 선택·기능 예시 전환을 브라우저에서 확인한다. 데스크톱과 모바일 캡처를 남기고 색 대비 계산 결과를 기록한다. 이번 단계에는 실제 API를 연결하지 않는다.

[단계 종료]
이번 변경, 검사 결과, 미완료·외부 미검증, 필요한 설정, 다음 번호를 docs/PROGRESS.md에 갱신하고 결정이 달라졌으면 docs/DECISIONS.md에 근거를 남겨라. 수행하지 않은 검사·연동·저장을 완료라고 보고하지 마라. 필수 조건이 실패하면 다음 입력 전에 해결할 항목을 밝혀라. 최종 답변은 구현 결과·확인 결과·남은 항목·다음 번호만 간결하게 작성하라.
