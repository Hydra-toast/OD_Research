Research Landscape — 11/14 실제 분석·피드백·버전과 백그라운드 작업

[이전 단계 이어받기]
먼저 AGENTS.md와 docs/PRODUCT_CONTRACT.md, docs/PROGRESS.md, docs/DECISIONS.md, docs/TEST_MATRIX.md를 읽어라. 계약 파일이 없다면 1번이 아직 적용되지 않은 것이므로 전제를 추측하지 말고 필요한 1단계 기록부터 복원하라. 기존 사용자 변경과 작동 기능을 보존하라.
지정된 이번 단계만 구현·검증하고 다음 번호를 자동 실행하지 마라. 선행 결손은 이번 작업에 필요한 범위에서 먼저 수정하라. 키·계정이 없으면 독립 구현과 고정 응답 테스트를 진행하되 실제 연동은 미검증으로 남겨라. 보안이나 데이터 무결성 전제는 우회하지 마라.

11/14단계: P1 전체 흐름을 완성하라.

[분석 연결]
실검색 → 관련성/역할 구성 → 확보 자료 분석 → 방향 카드 → 선택 → 근거 준비를 연결한다.
5단계의 초록 8편·방향별 문헌 2편 기준을 실자료에도 적용한다. 데이터가 부족하면 부족한 결과만 제공한다.
기본 추천 4~6편과 방향 3~5개는 목표 수이며 강제 개수가 아니다. 원문 없는 논문의 정밀 공정 비교는 지원하지 않는다.
관련성·최신성·인용수는 구분해서 제시하고 불투명한 종합 권위 점수는 만들지 않는다. ‘Landmark/Rising’은 검증된 근거가 없으면 사용하지 않는다.

[피드백과 버전]
랩미팅 피드백: 장비 없음, 기존 연구와 연결 약함, 다른 소재 비교, 최근 논문 보강, 자유 입력.
입력·자료·제약·선택·결과·모델/프롬프트 버전을 묶어 AnalysisVersion에 저장한다.
피드백은 새 버전을 만들고 이전 결과와 사용자 메모를 보존한다. 조건 변화·추가/제외 후보·변경 이유를 비교한다.
사용자가 제거한 제약을 계속 적용하거나 AI 결과가 사용자 수정을 덮어쓰지 않도록 구분한다.

[작업 실행]
PostgreSQL jobs 테이블 + 단일 Node worker로 시작한다. 별도 메시지 브로커는 추가하지 않는다.
상태: queued/running/succeeded/partial/failed/cancelled. 단계·오류·재시도 횟수·inputRevision·idempotencyKey·heartbeat를 저장한다.
작업을 원자적으로 가져오고 서버 재시작 시 방치된 running 작업을 복구한다. 중복 제출·중복 비용을 억제한다.
일부 논문 성공 결과는 보존하고 실패 항목만 다시 시도한다. 취소된 작업이나 오래된 버전은 최신 화면을 덮어쓰지 않는다.
진행률을 임의 퍼센트로 표시하지 않고 ‘논문 검색 / 근거 정리’와 완료된 문헌 수를 표시한다.

[P1 검증]
실제 모드 입력 → 검색어 수정 → 논문 추천 → 연구실 정보/동의 → 방향 선택 → 준비 → 저장/복원 → 피드백 새 버전까지 검사한다.
고정 응답으로 작업 재시작·429·AI 실패·부분 성공·취소·중복 제출을 재현한다.
실제 공급자·인증·AI·저장을 각각 실제 검증/모의 검증/미검증으로 기록한다. 모의 검증만 통과하면 P1 실연동 완료라고 하지 않는다.
외부 설정이 미완료여도 P2의 독립 코드 작업은 가능하지만, 실제 데이터 접근·업로드에는 인증과 소유권 검증을 반드시 통과시킨다.

[단계 종료]
이번 변경, 검사 결과, 미완료·외부 미검증, 필요한 설정, 다음 번호를 docs/PROGRESS.md에 갱신하고 결정이 달라졌으면 docs/DECISIONS.md에 근거를 남겨라. 수행하지 않은 검사·연동·저장을 완료라고 보고하지 마라. 필수 조건이 실패하면 다음 입력 전에 해결할 항목을 밝혀라. 최종 답변은 구현 결과·확인 결과·남은 항목·다음 번호만 간결하게 작성하라.
