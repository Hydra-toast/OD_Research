# 온닷 — 개인 연구 도구 PRD

| 항목 | 내용 |
|---|---|
| 버전 | v3.0 |
| 최초 작성일 / 개정일 | 2026-10-19 / 2026-10-28 |
| 기준 | 현재 프로젝트 코드와 기록된 검증 결과. 공개 배포본과 동일하다고 가정하지 않는다. |
| 사용자 | 새로운 연구 주제를 조사하고 논문을 읽고 설명해야 하는 개인 연구자 |
| 핵심 가치 | 선택한 논문의 연구군과 읽기 순서를 이해하고, 자료를 바탕으로 조사 내용을 설명한다. |
| 기본 방식 | 논문 검색·자료 관리와 외부 AI에 전달할 프롬프트 준비. 사용자가 AI에 직접 전달하고 결과를 가져온다. |

## 1. 제품 정의와 범위

온닷(이전 이름: 온닷사이, ONDOT Research, Research Landscape)은 사용자가 연구 주제를 입력하고 논문을 모은 다음, 제목·초록으로 우선 읽을 논문을 고르고 원문을 확보해 연구군과 논문별 내용을 정리하는 개인 연구 도구다. 기존 조사 결과와 출처를 다음 조사로 이어가는 기능도 제공한다.

특정 전공으로 검색을 제한하지 않는다. 논문 전체의 자동 분석이나 분야 전체를 대표하는 지도를 보장하지 않는다. 연구군 분류·읽기 추천·설명문은 사용자가 전달한 자료에 근거해 외부 AI가 생성한다. 웹페이지는 프롬프트 생성과 자료 관리, 결과 가져오기를 담당한다.

**핵심 사용 흐름:** 주제 검색 → 논문 선택 → 초록 선별 프롬프트 복사 → 외부 AI의 추천 결과 가져오기 → 추천 논문 자동 선택 → 원문 확보 → 상세 정리 프롬프트와 PDF를 외부 AI에 전달 → 상세 결과 저장 → 지식 지도 재사용.

처음부터 모든 과정을 완료할 필요는 없다. 원문이 없으면 초록 중심 선별을 할 수 있고, 상세 정리는 텍스트 전달 대안도 있다. 실제 검색 실패를 가상 예시로 대체하지 않는다.

## 2. 현재 기능과 판단 경계

| 기능 | 현재 프로젝트의 동작 | 확인 범위 |
|---|---|---|
| 주제 검색과 논문 수집 | OpenAlex 주 검색, Crossref 서지 보완·장애 대체. 선택·거르기·추가 검색과 규칙 기반 관련성 정렬 제공 | 현재 코드 기준. 실제 공급자와 공개 배포의 상태는 별도 확인 필요 |
| 1단계 초록 선별 | 선택 논문의 제목·초록을 넣은 짧은 프롬프트를 복사하고 외부 AI 결과를 가져옴 | 사용자 결과 예시 및 가상 자료 기반 브라우저 검사 기록 있음. 실제 AI의 준수는 보장하지 않음 |
| 추천 선택 | 추천 결과에서 1~5편을 원래 논문 ID에 연결해 선택하고 원문 단계로 이동 | 자동 검사 기록 있음. 잘못된 번호는 기존 선택을 보존 |
| 원문 확보 | 직접 열기, 공개 원문 일괄 받기, 선택 폴더 PDF 확인, 로컬 PDF 업로드 경로 | 공급자·환경에 따라 제한. 실제 공개 사이트 일괄 성공은 미검증 |
| 상세 정리 | 모델 공통 PDF 첨부 지시서 또는 초록·본문 발췌 지시서 생성, 결과 가져오기와 버전 저장 | 프롬프트 생성과 가져오기 검증. 실제 AI 출력과 원문 정확성은 별도 확인 |
| 지식 지도 | 상세 정리 이력과 출처를 파일로 내보내고 다른 조사에 불러옴 | 가상 자료 기반 저장·재열기·파일 전달 검사 기록 있음. 자동 의미 검색이나 시각화는 없음 |

검사 통과는 기록된 시점과 범위에 한정한다. 사이트에서 사용자가 확인한 성공, 자동화 테스트, 실제 외부 AI 사용, 공개 배포는 서로 다른 상태다.

## 3. 실제 사용자 흐름

### 3.1 주제 입력과 논문 선택

1. 시작 화면에서 연구 주제나 조사할 내용을 입력한다. 상담 프롬프트를 이용한 검색어 준비는 선택 사항이다.
2. 검색 결과를 확인하고 논문을 선택한다. 필요한 경우 포함·제외 단어와 연도 조건을 조정하거나 추가 검색한다.
3. 정렬은 제목·초록·검색 조건 등을 이용하는 `rule-v1` 규칙 기반 정렬이다. 의미 이해, 과학적 품질, 중요도나 연구 성장세를 판정했다고 표현하지 않는다.
4. 가상 예시는 별도 표시하며 실제 검색 실패를 예시로 대체하지 않는다.

### 3.2 1단계: 초록으로 읽을 논문 선별

1. 선택 논문의 제목·초록을 포함한 1단계 프롬프트를 복사한다. PDF 첨부는 필요하지 않다.
2. 사용자가 Gemini 또는 다른 외부 AI에 붙여 넣는다. AI에는 연구군과 접근법을 2~3문장으로 설명하고, 추천 논문 3~5편과 각 이유를 간결하게 제시하도록 요청한다. 용어는 필요한 곳에서 짧게 설명한다.
3. 추천 이유는 외부 AI 대화에서 읽는다. 웹페이지의 **결과 가져오기**에 답변 전체 또는 `선택 논문: [P번호], [P번호]` 줄을 넣고 **추천 논문 선택하고 다음 단계로**를 누른다.
4. 사이트는 프롬프트 생성 당시의 번호와 논문 ID를 대조하여 추천 1~5편만 선택하고, 선택 목록을 보여 주며 원문 확보 영역으로 이동한다. 사용자가 이후 직접 수정할 수 있다. 다운로드는 자동 시작하지 않는다.
5. 결과가 불명확하거나 번호가 범위 밖이면 입력과 기존 선택을 보존하고 오류를 표시한다. 상세 정리는 별도의 **선택 변경 없이 상세 정리본만 저장** 버튼을 사용한다.

제목·초록만으로 판정하므로 본문 내용을 읽었다고 표현하지 않는다. 연구군과 추천은 선택된 자료 안의 잠정 결과다.

### 3.3 2단계: 원문 확보와 연결

- 논문 상세의 개별 원문 작업은 공개 원문 또는 논문 페이지를 직접 연다. OpenAlex 콘텐츠 PDF는 서버의 인증된 `/api/openalex-pdf` 경로로 전달된다. 사이트를 여는 것과 파일을 저장한 것은 다르다.
- **원문 모두 받기**는 선택한 논문의 공개 원문 후보를 먼저 시도한다. OpenAlex 콘텐츠 PDF가 있으면 인증된 경로를 우선 사용하고, 해당 경로가 실패하면 기존 공개 원문 후보를 시도한다. 처리 상태와 취소를 제공한다.
- 로컬 서버의 일괄 처리에는 공개 원문 실패 후 DOI가 있는 논문을 Sci-Hub 직접 HTTP 경로로 한 편씩 시도하는 코드가 있다. 로봇 확인이 발생하면 이후 시도를 멈춘다. 공개 배포용 구성에서 Sci-Hub 경로는 로컬 전용으로 제한되므로 같은 자동 다운로드가 공개 사이트에서도 작동한다고 가정하지 않는다.
- 사용자가 외부 사이트에서 직접 받은 PDF는 선택한 조사 폴더에 넣고 **선택한 폴더의 PDF 확인**을 눌러 연결할 수 있다. 첫 두 쪽에서 찾은 DOI가 한 논문에만 일치하면 연결하고, 그 외는 사용자가 고른다. 파일명이 달라도 본문 DOI로 연결할 수 있다. 지속적인 다운로드 폴더 감시는 아니다.
- 개별 PDF 업로드 경로는 로컬 서버에서 처리한다. 공개 환경에서 해당 업로드 API를 사용할 수 있다고 보장하지 않는다.

새로 받은 PDF는 사용자가 선택한 폴더 또는 브라우저 다운로드로 저장을 요청하며 PDF 원본을 새로 IndexedDB에 보관하지 않는다. 폴더를 선택하면 그 아래 `Research Landscape/조사-ID`를 사용한다. 권한은 현재 탭에서 유지되며 재접속 시 다시 선택해야 한다. 폴더 미선택·실패 시 브라우저 다운로드를 요청한다. 브라우저의 실제 저장 위치·다중 다운로드 허용은 브라우저 설정에 따른다.

OpenAlex 일괄 경로는 PDF 20MiB 및 최대 100쪽 추출을 적용한다. 공개 서버의 일반 PDF 수집은 3MiB 파일 및 4MiB 응답 제한이 있다. 원문 링크 발견, 파일 수신, 텍스트 추출, AI 첨부, 사용자의 내용 확인은 각각 다른 상태다. 추출 텍스트는 브라우저 저장소에 남는다. 스캔 PDF의 OCR은 없다. 기존 브라우저 보관 PDF는 삭제하지 않고 저장할 수 있다.

### 3.4 3단계: 상세 정리

1. **PDF 첨부용 상세 정리 프롬프트 복사**를 누른다. 프롬프트에는 선택 논문의 `[P#]`, 제목, DOI 및 확인 가능한 파일명이 들어간다. PDF 본문 자체는 포함되지 않는다.
2. 외부 AI에 프롬프트를 붙여 넣고 선택한 PDF를 직접 첨부한다. 파일이 누락·식별 불가·읽기 불가이면 AI가 해당 논문마다 `[Pn] 논문명 - 파일 첨부 필요`만 출력하도록 지시한다. 모든 파일이 준비된 뒤 정리 시작을 요청한다. 실제 모델의 지침 준수는 별도 검증 대상이다.
3. AI에는 조사 질문과 결론, 연구군·접근법 차이, 논문별 문제·방법·조건·결과·의미, 논문 간 비교, 설명용 종합 문단, 남은 질문, 다시 볼 곳을 요청한다. 5편 기준 4,000~7,000자는 참고치이며 근거에 따라 달라질 수 있다. 수치·단위·조건·확인한 위치를 연결하도록 요구한다.
4. AI가 생성한 상세 결과를 웹페이지의 **결과 가져오기**에 붙여 넣거나 `.md`를 선택한 뒤 **선택 변경 없이 상세 정리본만 저장**을 누른다. 선택은 바뀌지 않으며 결과는 버전으로 보존된다. 웹페이지의 형식 검사는 사실 검증이 아니다.

PDF 첨부가 어려우면 **PDF를 첨부할 수 없을 때**에서 초록·확보한 본문 발췌 프롬프트를 복사할 수 있다. 본문 발췌는 논문당 최대 12,000자이며 그림·표·뒷부분이 빠질 수 있다. 제목·DOI만으로 원문 내용을 만들어서는 안 된다.

### 3.5 누적 지식 지도와 후속 조사

상세 정리 결과를 웹페이지에 저장하면 현재 조사의 상세 정리 이력과 논문 출처가 지식 지도에 포함된다. 1단계 추천 결과는 제외한다. 화면에는 `전문 도우미 지침 포함 · 누적 정리 N건`을 표시한다. 별도의 학습 보고서를 출력하지 않도록 프롬프트에 지시한다.

**같은 조사:** 누적 정리가 있는 상태에서 다음 프롬프트를 만들면 `research-knowledge.md`의 다운로드를 요청한다. 사용자는 프롬프트와 함께 그 파일을 외부 AI에 첨부한다. 다운로드가 안 되면 **지식 지도 .md 저장** 또는 **지도 내용 복사**를 사용한다.

**새 조사:** 이전 조사의 지도 파일을 **이전 지도 불러오기**로 웹페이지에 연결한다. 새 프롬프트를 만들고 연결된 지도 파일을 다시 AI에 첨부하거나 내용을 붙여 넣는다. AI 답변을 다시 저장하면 해당 조사의 누적 기록에 추가된다. 불러온 지도 연결 해제는 원래 파일이나 현재 조사 정리본을 삭제하지 않는다.

모델 자체의 재학습, 영구 기억, 새 대화에 대한 자동 접근은 없다. 지식 지도는 이전 정리 기록이며 원문 검증을 대체하지 않는다. 동일한 기록은 중복 제거하고 수정된 기록은 보존한다. 과거 기록은 고유 K키와 기록별 P번호로 구분해 현재 `[P#]`와 섞이지 않도록 지시한다. 같은 파일이나 불러온 지도 합계가 2MiB를 넘으면 가져오지 않는다. 파일 분할, 관련 기록 자동 검색·압축, 시각적 지도는 아직 없다.

## 4. 기능 요구사항

| ID | 요구사항 | 현재 경계 |
|---|---|---|
| FR-01 | 자유 주제 입력, 실검색과 예시 구분 | 전공을 제한하지 않음 |
| FR-02 | 상담·영문 검색식 외부 AI 프롬프트와 결과 확인 | 사용자 복사·가져오기. AI 자동 호출 없음 |
| FR-03 | OpenAlex 검색, Crossref 보완·대체, 중복 제거와 출처 보존 | Semantic Scholar를 재도입하지 않음 |
| FR-04 | 논문 선택, 거르기, 추가 검색과 규칙 정렬 | 정렬을 AI의 의미 판단으로 표현하지 않음 |
| FR-05 | 초록 기반 짧은 추천과 가져온 추천의 자동 선택 | AI가 생성한 추천만 파싱. 논문 원문 자동 다운로드 없음 |
| FR-06 | 공개 원문 개별 열기와 일괄 수집, 실패·취소 표시 | 공개·로컬 서버 경로 및 공급자별 제한 상이 |
| FR-07 | 사용자가 선택한 폴더의 PDF 확인과 DOI 연결 | 사용자 실행 필요, 자동 감시 없음 |
| FR-08 | PDF 첨부 또는 발췌 기반 모델 공통 상세 정리 프롬프트 | 파일 직접 첨부 필요. 모델의 지침 준수 미검증 |
| FR-09 | 상세 결과 저장·편집·버전 및 Markdown 내보내기 | AI 내용의 정확성 자동 검증 아님 |
| FR-10 | 상세 정리 기록의 지도 내보내기·불러오기·재전달 | 모델의 영구 학습이나 자동 기억 아님 |
| FR-11 | 선택·메모·비교·근거 및 저장한 조사 관리 | 기존 부가 기능은 보존하되 핵심 플로우와 구분 |
| FR-12 | 오류·불완전 자료·손상 입력에서 기존 내용 보존 | 사용자 확인·복구 경로 제공 |

## 5. 저장과 데이터

- 조사 정보, 선택, 메모, 정리 이력, 불러온 지도와 추출된 텍스트는 해당 브라우저의 IndexedDB에 저장한다. 계정 간 동기화가 아니다.
- 새로고침·새 탭 진입 시 주소에 조사 ID가 있어도 저장된 조사가 자동으로 열리지는 않는다. **저장한 조사** 목록에서 다시 연다.
- 조사 기록에는 논문 ID와 정리 시점의 제목·DOI 스냅샷을 남긴다. 이전 기록에 스냅샷이 없으면 현재 논문 정보로 연결을 시도하고 없으면 확인 필요로 남긴다.
- 지식 지도 `.md`에는 지침과 구조화된 상세 정리 기록이 들어 있다. 이 사이트가 내보낸 형식만 지식 지도 가져오기로 읽는다. 잘못된 파일은 기존 기록을 변경하지 않는다.
- 기존 조사 백업과 Markdown 내보내기는 별개다. JSON 조사 백업에 새 PDF 원본이 포함된다고 표현하지 않는다. 실제 백업·복원의 전체 범위와 오래된 자료 호환성은 별도 검증한다.

## 6. 화면 구성과 사용성

기본 `/`는 통합 작업 화면이다. 데스크톱은 논문 목록과 작업 영역을 나누고, 작은 화면은 목록과 작업을 전환한다. 작업 영역은 논문 상세, 연구군·읽기 순서, 비교·활용으로 구성된다. 저장한 조사와 PDF 폴더·조사 기준·정리본 이력은 보조 화면에서 접근한다. 이전 `/parallel.html`은 기본 화면으로 이동하는 호환 경로다.

기본 순서는 초록 선별 → 추천 선택 → 원문 확보 → 상세 정리다. 1단계의 긴 AI 답변을 다시 읽게 하기보다 추천 논문 선택과 다음 단계 이동을 우선한다. 실제 오류·자료 누락·가상 예시는 표시하되 반복적인 경고 문구로 작업을 방해하지 않는다. 표시·접근성의 실제 브라우저 확대와 기기별 품질은 별도 검증한다.

## 7. 실행 환경과 한계

| 항목 | 현재 기준 |
|---|---|
| 검색 | OpenAlex·Crossref. OpenAlex 콘텐츠 다운로드는 서버의 API 키가 필요하며 키를 클라이언트에 노출하지 않는다. |
| 개인 AI | 사용자가 직접 복사·첨부·결과 가져오기. 사이트가 개인 AI 계정에 로그인하거나 AI 모델 API를 자동 호출하지 않는다. |
| PDF 선택 폴더 | 브라우저 폴더 선택 기능과 권한에 의존한다. 실제 OS·브라우저 조합별 검증 필요. |
| 공개 서버 | 공개 검색 및 공개 PDF 경로가 구성되어 있으나 로컬 전용 업로드·Sci-Hub 경로와 다르다. 실제 배포본의 기능·설정은 별도 확인. |
| 원문 접근 | 공급자 인증·이용량·권한·서비스 응답에 따른다. 로봇 확인을 우회하거나 자동으로 풀지 않는다. |
| 공개 OpenAlex 키 | 현재 공개 경로에 전체 사용자 대상의 지속적인 호출량 제한이 없어 사용량 악용 위험이 있다. |

사이트의 기능이 PDF에 접근할 수 있다는 사실과 논문의 재배포 권한, 연구 내용의 정확성은 서로 다르다. 지식 지도와 AI 정리 역시 원문 근거를 대신하지 않는다.

## 8. 검증 기록과 미완료 사항

| 범위 | 현재 기록 |
|---|---|
| 지식 지도 | checkJs, 관련 Vitest 36개, Chrome E2E 2개 통과 기록. 상세 결과 저장·출처 스냅샷·다른 조사 불러오기·재열기·중복·잘못된 파일 보존을 가상 자료로 확인. |
| 1단계 추천 | 사용자 제공 결과와 가상 자료로 P번호 연결·추천만 선택·잘못된 입력 보존·원문 단계 이동 검사 기록. |
| OpenAlex 일괄 수정 | 모의 PDF로 인증된 스트리밍 경로와 다운로드 요청 검사 기록. 사용자가 보고한 공개 사이트의 실제 일괄 실패가 해결되었는지는 미검증. |
| 공개 사이트 | 현재 작업 디렉터리와 공개 배포본이 일치한다고 확인하지 않았다. 실제 배포 및 최신 기능 동작은 별도 검증. |
| AI 결과 | 실제 Gemini 및 다른 모델의 PDF 읽기, 누락 규칙 준수, 연구군 품질·수치·후속 맥락은 검증하지 않았다. |

기존 전체 검증 이력은 [진행 기록](../docs/PROGRESS.md)과 [검증 매트릭스](../docs/TEST_MATRIX.md)를 따른다. 기록된 검사는 당시 결과이며 이번 문서 개정으로 다시 실행했다고 간주하지 않는다.

## 9. 후속 개발 우선순위

1. 공개 사이트의 현재 배포본과 환경 설정을 확인하고 실제 OpenAlex 원문 한 편으로 개별·일괄 흐름을 각각 검증한다. 공개 API 접근 및 사용량 제한을 검토한다.
2. 실제 외부 AI에 PDF와 지도 파일을 전달해 파일 식별, 누락 응답, 출처·수치·상충 내용, 후속 질문의 유용성을 확인한다.
3. 누적 지도가 커질 때 선택 내보내기·분할 및 관련 자료 선택을 설계한다. 현재 2MiB 가져오기 제한을 넘어서는 자동 축적을 주장하지 않는다.
4. 실제 폴더 권한, 다양한 PDF, 스캔·추출 실패, 브라우저 다중 다운로드와 백업·복원 범위를 검증한다.
5. 연구군과 읽기 순서가 사용자의 이해를 돕는지 관찰하고, 불필요한 입력·클릭을 줄인다.

클라우드 동기화·계정 기반 공유·모델 API 연동·OCR·자동 연구 공백 발견·과제 수주 보장·복잡한 인용 그래프·유료 기능은 현재 핵심 구현으로 간주하지 않는다. 기존 관련 코드를 삭제하라는 의미는 아니다.

## 10. 문서 관리

이 문서는 최신 코드와 실제 검증 기록을 구분하는 제품 기준이다. 과거 `summary-v2`, Gemini 전용 `summary-v3-gemini`, `data/inbox-pdfs` 수신함 중심 흐름과 PDF 원본 브라우저 자동 보관은 현재 기본 작업 흐름을 설명하지 않는다. 현재 상세 프롬프트는 `summary-v4-portable`이다. 이전 요구사항은 [v2.3 원본](../docs/Research-Landscape-PRD-v2.3-archive.md)에 보존하고, 과거 결정과 검증의 맥락은 [결정 기록](../docs/DECISIONS.md)과 진행 기록에 남긴다.

제품 변경 시 이 문서와 제품 계약·진행 기록을 함께 갱신하고, 구현·자동 검사·실제 외부 연동·배포를 구분한다. 사용자의 저장 자료, 기존 변경과 `research-landscape-prompts/` 원본은 임의로 삭제하거나 수정하지 않는다.
