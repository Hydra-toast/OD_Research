## 1. 제품 정의와 이번 개정의 결정

Research Landscape는 교수님 말씀과 연구 메모를 출발점으로, 조사 질문과 여러 검색식을 준비하고 논문을 모아 비교·정리하는 개인 연구 도구다. 사용자가 이미 쓰고 있는 외부 AI와 논문 검색 서비스를 연결하는 작업 공간이며, 선택한 자료와 판단 근거를 다음 조사와 랩미팅에서 다시 사용할 수 있게 한다.

사이트 내부에서 AI 모델을 호출하지 않는다. 상담, 검색식 생성, 논문 해석, 연구 방향 검토, 발표 초안처럼 언어적 판단이 필요한 일은 외부 AI에서 수행한다. 사이트는 필요한 입력을 정리하고 적절한 지시문을 먼저 작성하며, 외부 AI의 응답을 검토 가능한 형태로 가져온다. 사용자는 외부 AI를 쓰지 않고 직접 작성해도 주요 기능을 사용할 수 있다.

| 유지할 뼈대 | 새 개발 기준 |
|---|---|
| 기존 HTML/CSS/JavaScript 및 Express | 다른 프레임워크나 새 사이트로 재구축하지 않는다. |
| 탐색·랩미팅 준비 화면 | 판매용 랜딩보다 실제 입력·자료 검토·저장한 조사 접근을 우선한다. |
| OpenAlex·Crossref 검색 | 여러 검색식을 실행해 통합하고 근거를 보여주는 규칙 정렬을 기본으로 한다. |
| 논문 선택·비교·메모·근거·방향 카드 | 자동 AI 생성 대신 수동 작성 또는 외부 AI 결과 가져오기를 연결한다. |
| IndexedDB·저장 복원·내보내기 | 로컬 보존을 기본으로 하고 전체 백업·복구를 중요 기능으로 둔다. |
| 원문 후보와 파일 처리 구조 | 원문 확보·텍스트 추출·사용자 확인을 구분한다. |
| 예시·실자료 구분과 검증 도구 | 가상 예시를 실제 논문으로 사용하거나 실패를 예시로 덮지 않는다. |

계정 가입, Supabase, 모델 API 키, 모델 사용료 결제, 클라우드 배포는 개인용 핵심 기능의 전제 조건이 아니다. OpenAI·Gemini 등 무료 API가 존재하더라도 이번 기본 방향에 자동 호출을 추가하지 않는다. 외부 AI의 구독·한도·데이터 처리는 사용자가 선택한 서비스의 조건을 따른다. 논문 검색·원문 공급자도 무료 또는 무제한이라고 보장하지 않는다.

이 문서는 이전 PRD와 변경 프롬프트의 충돌하는 제품 요구보다 우선한다. 기존 코드·저장 자료·환경변수는 임의 삭제하지 않는다. 이전 요구를 제외하거나 보류하는 것은 이미 만들어진 기능을 검토 없이 제거하라는 뜻이 아니다.

## 2. 해결할 문제와 개인 사용 기준

### 2.1 해결할 문제

- 교수님 발언이 짧고 넓어서 조사 질문과 영문 검색어로 바꾸기 어렵다.
- 외부 AI에 매번 배경·조건·출력 형식을 설명하는 일이 반복된다.
- 영문 검색어 하나로는 표현과 접근 방법이 다른 논문을 놓친다.
- 검색 결과를 합치고 중복을 없애며 읽을 순서를 정하는 데 시간이 든다.
- 여러 AI 대화와 논문 파일에 메모·근거가 흩어진다.
- 초록 기반 해석, 실제 본문 확인, 사용자 판단이 섞이기 쉽다.
- 피드백 후 이전 선택·근거·검색 조건을 보존하면서 조사를 이어가기 어렵다.

### 2.2 사용 분야

특정 전공 입력을 차단하지 않는다. 기존 EUV PR·ALD·HBM 예시는 유지하되 반도체 전용 용어·비교 항목을 모든 프로젝트에 강제하지 않는다. 고분자·소재·화학 등도 같은 검색·정리 기능을 사용한다. 분야별 실험 항목은 사용자가 정하거나 외부 AI와 검토한 후 적용한다.

교수님이 말한 약어의 의미, 특정 재료명, 연구실 장비는 확인되지 않았다면 가정으로 남긴다. 예컨대 MSN 같은 약어를 하나의 뜻으로 자동 확정하지 않는다. 잠정 해석으로 초기 검색은 준비할 수 있으나 어떤 해석을 사용했는지 확인할 수 있어야 한다.

### 2.3 개인 도구의 성공 기준

공개 서비스 전환율·유료 전환·출시 지표 대신 다음을 확인한다. 현재 달성 수치나 시간 절감 효과를 주장하지 않는다.

| 질문 | 확인 기준 |
|---|---|
| 곧바로 조사를 시작할 수 있는가? | 입력을 넣어 복사 가능한 상담 자료를 만들고, 영문 검색식을 가져오거나 직접 작성할 수 있다. |
| 여러 관점을 조사할 수 있는가? | 독립 검색 결과·중복 제거·부분 실패와 발견 경로를 확인할 수 있다. |
| 읽을 순서를 이해할 수 있는가? | 관련성 정렬의 근거와 판단이 제한된 자료를 구분한다. |
| 내 판단과 근거를 보존하는가? | 논문 선택·메모·조건·발췌·외부 AI 평가가 저장과 출력에서 유지된다. |
| 다음 작업으로 이어지는가? | 브라우저 재접속·백업 복원·피드백 반영 후 이전 작업을 잃지 않는다. |
| 추가 AI API 지출 없이 작동하는가? | 모델 키가 없거나 기존 키가 남아 있어도 사이트가 모델 API를 호출하지 않는다. |

## 3. 범위와 기능 책임

### 3.1 담당 구분

| 작업 | 사이트가 수행 | 사용자가 외부 AI에서 수행 |
|---|---|---|
| 발언 해석·주제 구체화 | 원문·조건을 수집하고 상담 프롬프트 구성 | 의미 해석, 가정 표시, 확인 질문, 후보 제안 |
| 검색 계획 | 검색식 편집·형식 검사·실행 준비 | 여러 관점의 영문 검색식과 키워드 제안 |
| 논문 수집 | API 요청·캐시·중복 제거·출처 보존 | 실제 서지정보를 생성해서 보충하지 않음 |
| 기본 정렬 | 제목·초록·검색 조건에 대한 규칙 계산 | 선택적으로 의미상 관련성 재검토 |
| 논문 읽기·방향 비교 | 선택 자료·발췌·질문을 입력 묶음으로 구성 | 제공된 자료 범위 안에서 해석·비교 초안 |
| 랩미팅 준비 | Claim·근거·수정·내보내기 | 선택적으로 설명 문장·예상 질문 초안 |
| 저장·복원 | 원본·수정·버전·백업 유지 | 저장의 대체 수단으로 사용하지 않음 |

외부 AI를 이용하는 일은 사용자가 복사·붙여넣기 또는 직접 파일 첨부로 수행한다. 사이트는 AI 계정 로그인, 브라우저 세션·쿠키 활용, 자동 대화 전송으로 API를 대신하지 않는다. MCP는 외부 도구 연결 방식이며, MCP 호출 자체에 언어 모델을 반드시 연결할 필요는 없다.

### 3.2 기본·확장·제외 범위

- 기본 필수: 발언·조건 입력, 상담 프롬프트, 결과 가져오기·복구, 검색식 직접 편집, 다중 검색, 규칙 정렬, 선택·메모·비교·근거, 로컬 저장, 백업·복원, Markdown 내보내기.
- 개인용 확장: 논문 재검토·독해·방향 비교·발표 준비용 외부 AI 자료 묶음, 원문 파일·추출, 개인 원문 공급자/MCP 어댑터, 인쇄 품질 보완.
- 별도 요청 전 보류: 클라우드 동기화, 계정·다중 사용자 서비스, 공개 배포, 모델 API 연결, OCR, 복잡한 인용 그래프·장기 동향 자동화.
- 제외: 가격·구독·결제·유료 잠금·상품 FAQ, 준비도·적합도 점수, 연구 공백·신규성·과제 수주 보장, 자동 PPT 디자인, 일정 관리.

Sci-Hub 원문 확보는 직접 HTTP 어댑터로 구현했다. 논문 카드에서 DOI가 있는 한 편을 사용자가 명시적으로 요청하며, 기존 OpenAlex·Crossref 검색 공급자는 유지한다. MCP 프로세스 설치·호출은 현재 구현에 포함되지 않는다. 원문 연결 실패가 검색·정리를 막지 않도록 분리한다. 2026-10-22 실제 한 편 검증과 남은 제한은 12절에 기록한다.

## 4. 화면과 디자인 방향

탐색과 랩미팅 준비의 두 작업 화면을 유지한다. 저장한 조사, 연구실 조건, 검색식 편집, 근거 확인은 보조 영역으로 제공한다. 한 번의 필수 마법사에 모든 기능을 묶지 않는다.

| 영역 | 필요한 내용 |
|---|---|
| 시작 영역 | 교수님 말씀·자유 메모 입력, 선택 조건, 저장한 조사, 새 조사 |
| 외부 AI 준비 패널 | 목적 선택, 전달할 자료 선택, 완성된 프롬프트 미리보기·수정·복사 |
| 결과 가져오기 | 붙여넣기, 오류·보완 요청, 원본과 적용 내용 확인 |
| 탐색 | 확정/잠정 범위, 여러 검색식, 진행·부분 실패, 논문 목록·정렬·선택 |
| 랩미팅 준비 | 선택 논문·방향, 비교표, 문장·근거·확인 질문·출력 |
| 저장한 조사 | 이름·최근 수정·모드·열기·백업·복원·삭제 |

한국어 안내, 기존 통일 색상 토큰과 컴포넌트를 유지한다. 새 시각 정체성으로 교체하지 않는다. 의미 없는 과학 장식·성과 숫자·판매 CTA·FAQ는 두지 않는다. JSON은 복사·가져오기 기능의 내부 교환 형식이며 사용자는 주제·검색식·가정·오류를 일반 폼과 문장으로 확인한다.

데스크톱 1280px, 모바일 375px, 실제 브라우저 200% 확대에서 핵심 작업을 사용할 수 있어야 한다. 표는 내부 스크롤 또는 카드형 표시를 제공한다. 키보드·폼 라벨·포커스 복귀·reduced-motion을 지원하고 상태를 색만으로 구분하지 않는다. 일반 글자 대비 4.5:1, 큰 글자 및 필수 UI 3:1을 확인한다.

## 5. 상세 기능 요구사항

### FR-01. 개인 조사 시작과 원본 보존

- 현재 입력 문구 “무엇을 알아보고 있나요?”와 제목 “어떤 논문부터 읽을까요?”를 유지한다. 개인 메모·미팅 발언·교수님 말씀 모두 입력할 수 있으며 특정 관계나 상황을 필수로 묻지 않는다.
- 전공, 알고 있는 장비·재료·공정, 기간·제약을 별도 선택 필드로 둔다. 미입력은 미확인이며 제약 없음이 아니다.
- 최초 원문과 이후 수정본을 보존한다. 외부 AI가 고친 문장으로 원문을 대체하지 않는다.
- 주 행동은 “외부 AI에 전달할 내용 준비”, “상담 결과 붙여넣기”, “검색식 직접 작성”이다. 로그인·키 설정은 요구하지 않는다.
- 예시 버튼은 명시적으로 가상 자료만 연다. 검색이 꺼졌을 때 실제 입력을 조용히 예시로 바꾸지 않는다.

수용 기준: 원문·선택 조건이 분리 저장되고 조건 없이도 상담 자료 작성·수동 검색 준비가 가능하다.

### FR-02. 상담 및 영문 검색식 프롬프트

- 일반 코드의 템플릿으로 완성된 프롬프트를 만든다. 템플릿 채우기에 모델을 호출하지 않는다.
- 목표, 발언 원문, 사용자 조건, 가정 표시 규칙, 검색 목적, 허용 문법, 반환 형식을 포함한다.
- 개인 AI의 첫 응답에 후보 2~3개, 잠정 조사 주제·질문, 영문 핵심 키워드, 서로 다른 검색식 5~8개를 함께 요청한다.
- 사용자 주제 선택을 기다리며 검색식을 비우지 않도록 명시한다. 미선택이면 발언에 직접적인 넓은 초기 주제를 제안하고 사용자 확인 전임을 표시한다.
- 약어·재료가 불명확하면 잠정 해석을 assumptions에 남긴다. 확인 질문 1~2개는 unknowns에 담는다. 해석할 연구 대상 자체가 없을 때만 이유와 최소 질문을 반환하고 검색 실행을 보류한다.
- 검색식은 핵심 대상·방법, 동의어, 구조·특성, 조건, 관련 공정 등 입력에 맞는 관점을 나눈다. 특정 분야의 관점 5개를 일률적으로 강제하지 않는다.
- OpenAlex에 전달할 영문 단어·구를 사용하며 지원하지 않는 site:·필드 문법·논리 연산자를 생성하지 않도록 한다. 단순 어순 변경으로 개수를 채우지 않는다.
- 교수님 발언의 근거는 원문의 부분 문자열을 사용한다. 접두사나 AI 설명을 인용문에 넣지 않는다.
- 템플릿의 자리표시자를 실제 검색어로 바꾸고 필수 필드·개수·중복을 자체 점검하도록 요청한다.

수용 기준: 복사 결과에 현재 입력·조건·버전·검색식 출력 조건이 포함된다. 외부 AI 생성 품질은 실제 사용 결과로 따로 확인하고, 템플릿 문자열 검사만으로 보장하지 않는다.

### FR-03. 외부 AI 결과 가져오기와 보완

- 현재 consult-v1 및 JSON 코드 블록을 지원한다. 원본 응답을 보존하고 eval·스크립트·HTML을 실행하지 않는다.
- 스키마·필드 타입·문자 수·검색식 개수·고유 ID·검색 문법을 검증한다. 초과 데이터를 조용히 자르지 말고 수정 또는 분할을 안내한다.
- 주제명·연구 질문·core·검색식이 비면 검색 가능한 완료 상태로 표시하지 않는다.
- 오류에는 원래 발언, 이전 응답, 오류 항목과 완전한 반환 형식을 담은 보완 요청을 제공한다. 복사 실패 시 직접 선택할 수 있게 한다.
- 일반 문장도 메모로 보존하고 수동 필드 입력 또는 재요청을 제공한다. 사이트가 AI 없이 이해한 것처럼 자동 변환하지 않는다.
- 기존 1~4개 검색식은 경고 후 허용하고 신규 상담은 5~8개를 요청한다. 사용자가 일부를 제외해도 실행 가능하다.
- 적용 전에 명시 요구·사용자 조건·AI 가정·미확인·잠정 주제·검색식을 보여준다. 입력에 없는 근거는 확인 필요로 표시한다.
- 사용자는 주제·질문·키워드·검색식을 직접 수정할 수 있다. 가져온 내용은 기본적으로 외부 AI 결과이며 사용자 확인 상태를 별도로 둔다.

수용 기준: 빈 queries 사례가 검색 실행으로 넘어가지 않고 보완 가능하다. 잘못된 JSON을 붙여도 원문과 작업 상태가 사라지지 않는다.

### FR-04. 검색식 편집과 다중 검색

- 검색식별 ID·영문 텍스트·목적·활성 여부를 관리한다. 추가·수정·제외·개별 재실행을 제공한다.
- 첫 수집은 최대 8개 검색식, 동시에 최대 2개 작업을 기본값으로 한다. 공급자 제한이 더 낮으면 그 제한에 맞춘다. 각 검색식의 기본 첫 페이지는 최대 50편이고 추가 수집은 사용자 행동으로 시작한다.
- OpenAlex 주 검색과 Crossref 결측 보완·장애 대체를 유지한다. 두 공급자의 동등한 전수 통합 검색이라고 표현하지 않는다.
- 현재 키 선택·연락 이메일 처리 구조를 유지하되 공급자 조건은 구현·실사용 시 확인한다. Semantic Scholar 의존을 재도입하지 않는다.
- 정상 0건, 장애, 429 대기, 부분 성공을 구분한다. 개별 보완 실패로 정상 결과를 지우지 않는다. 모두 실패하면 확보 실패와 재시도 방법을 표시한다.
- 검색식별 결과·공급자·수집 시점·페이지·오류·캐시 상태를 보존한다. 실제 진행 개수로 상태를 보여준다.
- 범위 수정·취소 시 오래된 응답을 무시하고 기존 선택·메모를 유지한다. 동일 조건 중복 실행을 제한한다.

수용 기준: 복수 검색식의 결과와 실패 범위가 구분되며 미완료 검색을 전체 성공으로 표시하지 않는다.

### FR-05. 논문 통합과 출처

- DOI 정규화와 공급자 ID를 이용해 중복을 합친다. 제목만 같은 서로 다른 논문을 무리하게 병합하지 않는다.
- 통합 후 원래 공급자 ID·발견 검색식·필드별 출처·수집 시점을 보존한다. 중복 제거 전후 수집 수를 구분한다.
- 제목·저자·연도·학술지·초록·인용수·DOI·URL의 결측은 그대로 남긴다. AI 출력으로 실제 서지를 만들어 채우지 않는다.
- 공급자 추정 검색 수, 현재 수집 수, 외부 AI에 전달한 수를 별도로 표시한다.
- DOI 직접 추가는 조회 결과와 사용자 직접 입력을 구분한다. 서로 다른 모드의 자료 혼합 규칙을 유지한다.

수용 기준: 한 논문이 여러 검색에서 발견되어도 선택 목록에는 중복되지 않고 발견 경로를 확인할 수 있다.

### FR-06. 규칙 기반 관련성 정렬

- 기본 정렬은 코드가 계산한다. 제목·초록의 핵심 단어·동의어·선호 조건·제외 조건·독립 검색 경로를 사용한다.
- 기존 rule-v1을 초기 기준으로 유지하고 가중치·버전을 기록한다. 변경 시 예전 결과를 새 기준으로 계산했다는 사실을 남긴다.
- 초기 기준은 핵심 제목 일치 4점(상한 12), 초록 2점(상한 8), 동의어 묶음 제목 2/초록 1, 선호 1점(상한 4), 복수 검색 경로 보조 점수 최대 3점이다. 동점은 ID 순으로 고정한다. 확률·과학적 적합도 점수로 표현하지 않는다.
- 반복 단어·동의어·동일 검색식이 점수를 부풀리지 않도록 검사한다. 부분 문자열의 잘못된 일치와 약어 처리 한계도 실제 사례로 점검한다.
- “제목에 핵심 키워드 일치”, “여러 검색에서 발견” 등 실제 계산 근거를 템플릿으로 표시한다. 의미 이해를 한 것처럼 설명하지 않는다.
- 초록 없음은 판단 제한이다. 무관 또는 저품질로 확정하지 않는다.
- 제외는 사용자가 명시한 조건에만 적용하고 이유·해제 기능을 제공한다. 최신순·인용순은 별도 옵션으로 둔다.

수용 기준: 같은 자료·기준에서 순서가 재현되고 추천 근거가 실제 계산과 일치한다.

### FR-07. 외부 AI 작업용 입력 묶음

상담 이후에도 외부 AI에 무엇을 넣어야 할지 사이트가 준비한다. 각 작업은 선택 기능이며 사용자 직접 정리가 가능해야 한다.

| 작업 종류 | 준비할 입력 | 외부 AI에 요청할 결과 |
|---|---|---|
| 조사 구체화·검색어 보완 | 발언, 조건, 이전 계획, 검색 실패·0건 정보 | 잠정 주제, 검색식·동의어, 변경 이유·질문 |
| 논문 관련성 재검토 | 조사 기준, 선택 논문 ID·제목·초록 | 일치·불일치·미확인, 읽을 순서와 이유 |
| 논문 읽기 도움 | 한 논문의 확보 자료, 사용자 질문, 발췌·페이지 | 핵심 용어 설명, 읽을 항목, 자료 범위 안의 해석 |
| 연구 방향·연구실 연결 | 선택 논문, 실제 근거, 사용자 확인 연구실 조건 | 방향 후보, 근거 ID, 필요한 조건·약한 연결 |
| 논문 비교 | 비교 항목, 각 자료와 발췌, 알려진 단위·조건 | 비교 초안, 비교 불가 이유, 확인할 값 |
| 랩미팅 설명·예상 질문 | 선택 방향, Claim·근거·노트·미확인 | 설명 초안, 예상 질문, 추가 확인 목록 |
| 연구군·읽기 순서 (선택 논문 기본 분석) | 반복한 세부 검색으로 고른 논문, 공개 원문·Sci-Hub·사용자 PDF에서 실제 추출한 텍스트, 없으면 확보한 초록, 자료별 번호와 출처 | 연구군별 문제·접근법·분류 근거, 공통 입문 순서, 관심사별 경로와 추천 이유가 있는 md. 돌아온 md는 선택적으로 가져와 버전으로 보존하고 더 발전시킴 |
| 피드백 반영 | 이전 조사 기준, 교수님 피드백, 유지할 선택·메모 | 변경 제안, 보완 검색식, 보존할 내용 |

모든 묶음은 목적, 기준, 실제 포함 자료, 금지할 추정, 결과 형식, 자료 버전을 포함한다. 선택하지 않은 비공개 조건을 자동으로 넣지 않는다. 자료량이 많으면 제한을 고지하고 묶음 번호·포함 ID·누락 수를 표시한다. “전체 논문 검토”는 실제 전체를 전달한 경우에만 사용한다.

논문 분석용 결과물에는 지시문뿐 아니라 실제 논문 자료를 반드시 포함한다. 메타데이터만/초록만/원문 일부를 실제 전달 가능한 텍스트로 구분하고, 원문을 확보했더라도 전체를 전달한 것으로 표시하지 않는다. 현재 프롬프트는 논문별 원문 발췌 12,000자 제한과 잘림 표시를 사용한다. 입력 자료 묶음 자체의 파일 다운로드·전체 분량 기준 분할은 후속이며, 기존 정리본 Markdown 다운로드와 구분한다.

2026-10-22 기본 지침을 `summary-v2`로 변경했다. 출력은 한눈에 보기와 자료 범위 → 연구군 지도 → 공통 입문 읽기 순서 → 관심사별 읽기 경로 → 핵심 용어 → 한계와 추가 자료 → 출처 목록이다. 연구군은 문제·접근법으로 나누고 중복 소속·미분류를 허용한다. 공통 입문은 적합한 자료 안에서 최대 3~5편이며, 한 편·자료 부족이면 수를 채우지 않는다. 분류 해석과 학습 순서 제안은 사실과 구분하고 각 판단에 [P#] 근거와 이유를 요구한다. 메타데이터만으로 내용 분류·입문 추천을 확정하지 않으며 수집 자료를 분야 전체나 성장률로 일반화하지 않는다. 이는 외부 AI용 지침 구현이며 사이트 자체의 자동 군집화나 실제 AI 출력 품질 검증 완료를 뜻하지 않는다.

프롬프트와 입력 자료를 미리보기·수정·복사·Markdown 저장할 수 있게 한다. 토큰 수는 실제 측정하지 않았으면 정확한 값으로 표시하지 않는다. 사용자가 외부 AI에 PDF를 직접 첨부해야 한다면 필요한 파일을 명확히 안내한다. 원문 URL만 넘긴 상태를 본문 제공으로 보지 않는다.

### FR-08. 외부 평가 적용과 수동 정리

- 현재 review-v1은 관련성 검토에 사용한다. 비교·방향·Claim 가져오기는 별도 스키마와 버전을 정의한 뒤 제공한다. 읽기 도움처럼 자유로운 응답은 메모로 보존할 수 있다.
- 가져온 논문·근거 ID, 중복·누락·자료 버전, 위치 존재 여부를 검사한다. 자료 범위를 넘는 위치·수치는 확인된 값으로 채택하지 않는다.
- 규칙 정렬과 외부 AI 평가를 별도 필드로 둔다. 미리보기 후 사용자가 적용해야 순서나 비교값이 바뀐다. 되돌리기를 제공한다.
- 자료나 기준이 바뀌면 평가를 오래된 결과로 표시한다. 단순 정렬 알고리즘 이름만으로 자료 버전을 판단하지 않는다.
- 모델 이름은 사용자가 제공한 경우에만 기록한다. 형식 검증 통과는 내용의 정확성 검증이 아니다.

수용 기준: 없는 ID가 포함된 결과를 자동 적용하지 않고 누락 논문과 사용자 편집을 유지한다.

### FR-09. 연구실 정보와 방향 카드

- 연구실 정보는 선택이며 기존 논문·재료·장비·측정 역량·제약·확인 출처를 기록한다. 논문 속 장비를 보유 장비로 확정하지 않는다.
- 기존 방향 카드·비교 UI를 유지하고 직접 작성 또는 외부 AI 결과를 가져오도록 확장한다. 자동 생성된 실자료 방향이 있는 것처럼 예시를 끼워 넣지 않는다.
- 방향에는 질문, 연결 논문, 근거, 연구실과의 연결, 추가 조건, 불확실성, 다음 읽을 자료를 둔다.
- 개인 초기 가설은 문헌이 적어도 메모로 남길 수 있다. 과거의 8편 기준을 개인 작업 진입 차단으로 사용하지 않는다. 연결 문헌 2편 미만인 방향은 근거 부족으로 표시하고 문헌 수가 과학적 충분성을 보장한다고 말하지 않는다.
- 연구 방향을 외부 AI에 제안받을 때 실제 제공 문헌 수·자료 범위를 프롬프트에 포함한다.

### FR-10. 비교표·발표 문장·근거

- 비교 공통 항목은 목적, 접근법, 재료·공정, 결과, 적용 조건, 저자 한계, 조사와의 연결이다. 분야별 항목은 추가·수정할 수 있다.
- 수치에는 원값·단위·측정 조건·발췌·위치가 필요하다. 조건이 다른 수치를 단일 성능 순위로 만들지 않는다.
- 빈값은 자료에서 찾지 못함/원문 미확보/추출 실패/적용 안 됨으로 구분한다. 가상값으로 보충하지 않는다.
- Claim은 문장·근거·조건·해석·추가 확인을 갖는다. 사용자 작성, 외부 AI 초안, 사용자 수정의 출처를 구분한다.
- 문장을 바꾸면 근거 연결은 보존하되 사용자 확인 상태는 해제한다. 파일을 얻거나 스키마 검사를 통과했다고 검증 완료로 표시하지 않는다.
- 사용자가 요청하면 누락 근거·적용 조건·연구실 제약에 대한 확인 질문을 제시한다. 질문은 코드 규칙 또는 외부 AI용 프롬프트로 준비한다.

### FR-11. 로컬 저장·백업·복원

- IndexedDB를 기본 저장소로 사용하고 “이 브라우저에 저장” 상태를 표시한다. 계정 없이 목록·열기·이름 변경·자동 저장·삭제를 제공한다.
- 원문 입력·조건·가정·계획·검색식·수집 결과·출처·선택·메모·비교·Claim·외부 결과·버전을 보존한다.
- 탐색 중인 페이지와 경고, 제외 해제 등 사용자 선택도 복원한다. 자동 저장 완료 전에 다른 조사를 열어 최근 변경을 잃지 않게 한다.
- 전체 조사 백업은 버전이 있는 JSON으로 내보내고 다시 가져온다. Markdown 출력은 복구용 백업과 구분한다.
- 백업 가져오기 시 스키마·ID 참조·모드·파일 참조를 검사하고 충돌 시 새 조사로 복원하거나 사용자 확인 후 병합한다. 기존 데이터를 자동 덮어쓰지 않는다.
- 원문 파일이 별도 저장되면 백업에 포함된 파일과 누락 파일 목록을 표시한다. 텍스트 JSON만으로 PDF까지 백업했다고 표현하지 않는다.
- 손상 자료는 격리·원본 다운로드·복구 안내를 제공한다. 새 버전 자료는 읽기 전용 등 보존 가능한 방식으로 처리한다.
- 같은 브라우저를 사용하는 사람 사이의 계정 격리를 보장하지 않는다. 클라우드 동기화는 필수가 아니다.

### FR-12. 피드백과 버전

피드백을 입력하면 새 조사 기준과 작업 버전을 만들고 이전 자료·선택·메모를 유지한다. 조건 수정만으로 외부 AI 평가가 자동 갱신됐다고 표시하지 않는다. 변경된 조건과 영향을 받은 결과를 보여주고 보완 검색 또는 외부 AI 재검토용 프롬프트를 준비한다. 이전 버전으로 돌아갈 때도 현재 편집본을 잃지 않아야 한다.

### FR-13. 내보내기

연구 요약, 논문 목록·비교표, 주장·근거, 확인 질문, 외부 발표 도구에 넣을 안내를 복사·UTF-8 Markdown·인쇄로 제공한다. 필요한 그림은 실제 확보 위치 또는 “원문에서 확인 필요”로 표시한다. 자동 PPT 파일 생성은 요구하지 않는다.

출처·자료 범위·AI 해석·사용자 확인·가상 라벨을 모든 출력에 유지한다. 긴 자료는 본문과 부록으로 분리하고 내용을 숨기거나 과도하게 축소하지 않는다. 복사·파일 저장 실패 시 원문 텍스트를 유지하고 재시도할 수 있어야 한다.

### FR-14. 원문 수집·PDF 보관·선택적 MCP 확장

- 기존 OpenAlex·Crossref 원문 후보, 사용자 파일, 개인 원문 공급자 어댑터를 분리한다. 자동 수집·확보를 기본으로 켜지 않는다.
- Sci-Hub는 `POST /api/fulltext/scihub`의 직접 HTTP 어댑터로 DOI 조회→PDF 주소 해석→다운로드→형식 검사→본문 추출을 수행한다. 카드의 **Sci-Hub 원문 받기**로 한 편씩 요청하며, 서버 동시 요청은 1개로 제한한다. 검색·공개 원문 수집 도중 Sci-Hub를 몰래 호출하지 않는다.
- MCP와 모델 API는 현재 원문 수집의 의존성이 아니다. 별도 MCP 확장 시 실제 도구·출력·의존성을 확인하고 직접 HTTP 구현과 구분한다. 원문 수집 실패 시 일반 검색·수동 PDF 작업을 유지한다.
- 출처·접근 조건·확인 상태를 보존한다. URL 또는 소프트웨어 라이선스로 논문 재배포 권한을 확정하지 않는다.
- 현재 저장은 브라우저 IndexedDB의 원문 영역이다. PDF Blob과 페이지별 텍스트를 조사 ID·논문 ID에 연결하고 새로고침 후 복원한다. **보관 PDF 저장**으로 원본 파일 저장을 제공한다. 서버의 30일 임시 만료를 적용하지 않는다.
- 서버 전용 파일 보관과 PDF 포함 전체 백업은 후속 요구다. 현재 조사 JSON 백업에는 PDF가 포함되지 않음을 화면에 명시한다. 브라우저 사이트 데이터 삭제 시 PDF도 사라진다.
- 파일명은 DOI/논문 ID를 정제하여 생성한다. HTTPS·DNS 공인 IP·리다이렉트별 주소를 검사하고 실제 연결을 검사한 IP에 고정한다. 내부망 접근, 다른 출처 요청, 크기 초과를 거절한다.
- 초기 파일 제한은 PDF 20MB/100페이지, 프로젝트 5파일·총 100MB를 유지하고 필요 시 사용자가 명시적으로 조정하도록 설계한다. 서버 요청 크기 제한도 실제 허용 파일 크기와 일치시킨다.
- 서버가 실제 PDF 바이트를 검증·추출하고 원본과 추출 결과를 브라우저에 반환해야 한다. 요청에 들어온 pages 문자열을 저장한 것을 PDF 추출로 보고하지 않는다. 스캔·암호화·손상은 별도 상태로 남기고 OCR은 보류한다.
- DOI 형식 오류·다른 DOI 페이지·로봇 확인·원문 없음·접근 거절·시간 초과를 구분한다. 인증 확인은 자동 우회하지 않는다. 재시도 실패 시 기존 PDF/본문을 유지하고, 다른 조사로 이동한 뒤 도착한 응답을 새 조사에 적용하지 않는다.
- Sci-Hub 응답의 본문 DOI 일치 여부를 보존한다. 일치를 확인하지 못했으면 사용자 확인이 필요한 상태로 표시하며, 본문 DOI 일치를 논문의 모든 내용이 검증됐다는 의미로 사용하지 않는다.
- 후보 링크, 파일 확보, 텍스트 추출, 발췌 연결, 사용자 내용 확인을 구분한다. 파일 해시·추출기 버전·PDF 페이지와 인쇄 페이지 라벨을 보존한다.
- 조사 삭제 시 연결된 PDF와 본문을 같은 트랜잭션에서 삭제한다. 원문만 삭제할 때의 서지·메모 보존과 근거 재확인 처리는 후속 요구로 구분한다. 외부 AI에 원문을 자동 전송하지 않는다.

## 7. 정보 신뢰성과 전송 범위

- 실제 논문·DOI·저자·수치·페이지·그림 위치를 지어내지 않는다.
- 서지정보만/초록 확보/파일 확보/텍스트 추출/사용자 확인 상태를 하나로 합치지 않는다.
- 외부 AI 응답은 검토할 초안이다. 사용자 확인도 전문가 검증과 동일하지 않다.
- 예시 ID는 example:와 “가상 예시 · 실제 논문 아님” 표시를 사용한다. 사용자 제공 자료는 따로 표시하고 실제 검색과 가상 자료를 조용히 섞지 않는다.
- 검색 API에 전달하는 것은 사용자가 확인한 검색식과 필요한 필터다. 교수님 발언·연구실 메모 전체를 검색 요청이나 로그로 자동 전송하지 않는다.
- 외부 AI용 묶음은 복사 전 자료 범위를 보여준다. 사용자가 이후 다른 서비스에 붙여 넣은 자료를 사이트가 회수·삭제할 수 있다고 말하지 않는다.
- 제공 논문 수·기간·검색 범위가 없는 동향 수치와 분야 전체에 대한 단정을 만들지 않는다.

| AI | 템플릿 생성·수동 자료 전달·구조화 응답 가져오기. 모델 API 호출 없음 |

기본 설정은 PORT, SEARCH_ENABLED, 선택 OPENALEX_API_KEY, 선택 CROSSREF_MAILTO다. 개인용 핵심 사용에 OPENAI_API_KEY, GEMINI_API_KEY, 모델명, 일일 AI 예산, Supabase 설정을 요구하지 않는다. 기존 .env의 개인 값은 이번 문서 개정으로 수정하거나 삭제하지 않는다. .env.example와 README의 실제 정리는 후속 구현 범위다.

공급자 키·실제 이메일·로컬 경로·연구 메모를 브라우저 설정 응답이나 일반 로그에 노출하지 않는다. 정적 파일 허용 목록을 유지한다. 원격 접속·공개 배포는 별도 요청 전 자동으로 열지 않는다. 개인 서버라도 파일·URL 입력 검증과 요청 출처 검사를 적용한다. 멀티테넌트 운영 체계를 개인용 기본 요구로 만들지는 않는다.

## 9. 오류·성능·복구 요구사항

| 상황 | 요구 동작 |
|---|---|
| 개인 AI의 빈 검색식·질문만 있는 응답 | 원문 유지, 누락 표시, 즉시 사용할 보완 프롬프트 또는 직접 입력 |

| 공급자 제한 | 제한된 재시도·대기 상태, Retry-After 존중, 무한 루프 금지 |
| 기준 변경·늦은 응답 | 이전 응답 무시, 선택·메모 유지, 외부 평가 오래됨 표시 |
| 파일 미확보·추출 실패 | 서지·초록 작업 유지, 직접 파일 추가·수동 발췌 안내 |
| 저장 실패·탭 충돌 | 성공 표시 금지, 원본 유지, 복구·백업·충돌 선택 제공 |
| 외부 결과의 없는 ID | 적용 중단 또는 문제 항목 격리, 누락 범위와 이유 표시 |
| 서버 종료·재시작 | 임시 작업을 완료로 오인하지 않고 재시도 상태로 복구 |

캐시는 공급자·정규화 검색식·필터·페이지를 키로 구분한다. 초기 메타데이터 24시간, 검색 1시간, 0건 5분을 기준으로 삼되 실제 공급자 정책에 맞춰 조정한다. 개인 입력을 여러 사용자에게 공유하는 캐시를 만들지 않는다. 로그는 단계·오류 코드·경과 시간 중심으로 남기며 민감 본문을 제외한다.

## 10. 개발 우선순위와 완료 조건

아래는 작업의 우선순위와 범위다. 기존 14단계를 다시 실행하거나 완료로 간주하는 표가 아니다.

| 우선순위 | 작업 범위 | 완료 기준 |
|---|---|---|
| A: 개인 조사 기본 | FR-01~06, FR-11, FR-13의 기본 출력 | 외부 AI 또는 직접 입력으로 다중 검색하고 근거 있는 정렬·저장·백업 복원 가능 |
| B: 외부 AI와 반복 정리 | FR-07~10, FR-12 | 목적별 자료 묶음과 결과 검토·적용·되돌리기, 사용자 작업 보존 |
| C: 개인 원문 확장 | FR-14, 파일 백업·인쇄 보완 | 실제 파일 확보·추출·참조·삭제 검증, 공급자 실패 시 핵심 작업 유지. 직접 HTTP 구현과 미완료 백업/MCP를 구분 |

개발자는 작업 전 실제 코드와 변경 내역을 확인하고 현재 구현을 재사용한다. 한 작업에서 수정할 범위를 기록하고, 코드 수정 후 관련 검사를 실행한다. 이번 PRD 수정 요청 자체는 A~C 전체의 코드 구현 지시가 아니다. 기능 완료는 코드·사용 결과·검사 증거가 있을 때만 기록한다.

기존 인증·AI 예산·클라우드·worker 요구는 개인용 완료 조건에서 제외한다. 외부 AI 결과를 가져오는 구조와 로컬 데이터 보존이 우선이다. 소프트웨어 기본 구조는 유지하며 대규모 재작성이나 자동 커밋을 하지 않는다.

### 12.1 Sci-Hub 실제 한 편 검증 기록

2026-10-22 사용자 요청에 따라 실제 논문은 **1편**, Sci-Hub 다운로드 요청은 **1회**만 실시했다. DOI `10.1038/nature09492`, PDF 402,190바이트·4쪽, 페이지 구분 문자를 제외한 추출 텍스트 28,943자를 확인했다. 원본과 브라우저 보관본 SHA-256은 `f4e14e44a731e90b2ed5a59b71abbbfe1213746d741ade4209a4970ca4a3be33`로 일치했다. 본문 DOI 일치·재열기·원문 발췌의 개인 AI용 프롬프트 포함까지 확인했다.

코드 검사와 전체 단위 검사 171개가 통과했고, 마지막 저장/삭제 보완 후 관련 32개를 재확인했다. 고정 응답 화면 검사 1개와 실제 원문 화면 검사 1개가 통과했다. 단, 브라우저 OS 파일 저장은 canceled 상태를 별도 기록했으므로 완전한 다운로드 UI 성공으로 간주하지 않는다. 검색은 고정 서지정보를 사용했으며 OpenAlex 실검색 검증이나 전체 논문 확보율의 근거가 아니다.
