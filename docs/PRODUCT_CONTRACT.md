# Research Landscape 제품 계약

## 목적과 사용자
새 연구 주제를 받은 석사 신입과 초기 연구자가 다음을 찾도록 돕는 웹 서비스다.
- 분야의 연구 갈래
- 먼저 읽을 논문과 그 이유
- 연구실과의 연결
- 랩미팅에서 설명할 근거와 출처

초기 데이터 검증은 반도체 중심이다. EUV photoresist, High-k dielectric, ALD, HBM, GAA transistor, SiC, 2D semiconductor 등 입력을 허용한다. 자료가 부족한 영역은 지원 수준을 그대로 표시한다. 장기적으로 배터리·디스플레이·화학/소재·공학으로 확장할 수 있는 데이터 구조를 둔다.

## 작업 화면
1. 탐색: 연구 방향과 읽을 논문 찾기
2. 랩미팅 준비: 선택 내용 비교, 근거 확인, 발표 문장 편집, 내보내기

연구실 정보, 근거 패널, 범위 수정은 보조 패널이다. 필수 단계로 만들지 않는다.

## 고정 결정
- 프런트엔드: 기존 HTML/CSS/JavaScript 유지. ES modules와 파일 분리는 허용. Next.js/React로 이전하지 않는다.
- 서버: 8단계부터 Node.js + Express(JavaScript ESM). 프런트엔드와 API는 같은 출처.
- 검사: JSDoc + TypeScript checkJs, Vitest, Playwright.
- 저장: P0는 IndexedDB, P1은 Supabase PostgreSQL + Auth(이메일/비밀번호), P2 파일은 Supabase 비공개 Storage.
- 로그인 없는 P0는 해당 브라우저의 예시 프로젝트만 저장한다. 계정 보안이나 서버 접근 제어라고 부르지 않는다.
- 실검색: Semantic Scholar. DOI/서지 보완: Crossref. 원문: 사용자 업로드 또는 접근·이용 조건을 확인한 openAccessPdf.
- AI: OpenAI Responses API. 서버 환경변수 `OPENAI_API_KEY`, `OPENAI_MODEL=gpt-5.4-mini`. 이용 불가 시 다른 모델로 대체하지 않고 "설정 필요" 상태를 남긴다.
- 브랜드: Atlas를 Research Landscape로 교체. 헤더는 "사용 예시 / 저장한 조사". 인증 연결 후에만 로그인·계정 노출.
- 요금 섹션은 제거하고 FAQ로 통합. 가격·결제·유료 잠금은 범위 밖.
- 랜딩 예시는 EUV PR·ALD·HBM.
- 디자인은 3단계의 통일 토큰을 전 화면에 적용.
- 외부 연동은 현재 키 없이 진행한다. 어댑터와 고정 응답 검증까지만 하고 실연동은 "외부 조건으로 미검증"으로 기록한다.

## 금지사항
- 실제 논문·DOI·수치·원문 위치를 지어내지 않는다.
- 초록만 있으면 Figure·페이지·절 번호를 만들지 않는다.
- 원문 확보만으로 주장 검증 완료를 선언하지 않는다. 사용자 확인을 자동 부여하지 않는다.
- 연구실 장비·실행 가능성을 자료 없이 추정하지 않는다.
- 연구 공백 자동 발견, 과제 수주·랩미팅 통과 보장, 준비도/적합도 점수, 일정 관리, 자동 PPT 제작은 만들지 않는다.
- 실검색 실패를 예시 결과로 조용히 대체하지 않는다.
- 서버 보안을 끄거나 가짜 성공으로 검사를 통과시키지 않는다.

## 상태 구분
- 자료 접근: 서지정보만 / 초록 / 원문 / 사용자 제공
- 자료 출처: provider / user / example
- 주장: 출처 발췌 연결 / AI 해석 / 사용자 확인 / 추가 확인 필요
- 비교 셀 빈값: 자료에서 찾지 못함 / 원문 미확보 / 추출 실패 / 적용 안 됨

## 모드 경계
- 예시 모드: 가상 데이터. ID는 `example:` 접두사. 모든 화면·근거 패널·내보내기에 "가상 예시 · 실제 논문 아님" 표시.
- 고정 응답 모드: 테스트 전용 공급자. 명시적으로만 전환.
- 실제 모드: 실공급자만 사용. 실패 시 예시로 전환하지 않는다.
- 모드 혼합 저장·내보내기를 허용하지 않는다.

## 상품 가설 (검증 대상, 확정 아님)
무료 탐색과 향후 유료 "랩미팅 근거 정리". 가격·사용량·과제 단위/구독은 미정이며 현재 범위에서 구현하지 않는다.

## 단계
P0=1~7, P1=8~11, P2=12~14. 상세는 `PROGRESS.md`.


## 보완 계약
- 예시 프로젝트에 사용자 제공 자료(`user:`)를 섞을 수 있다. 화면·내보내기에 "사용자 제공 자료 · 확인 전"과 가상 예시 혼합 안내를 표시한다.
- 실제 공급자 자료는 예시 프로젝트에 넣지 않는다(실모드는 8단계 이후).
- 수치 셀은 단위·측정 조건·근거를 연결해야 하며, 단위·조건이 다르면 직접 비교를 제한한다.
