# Research Landscape 제품 계약

## 2026-10-28 Gemini 추천 동선

Gemini 추천 시 검토 대상은 선택한 논문 최대 100편이며, 초록이 있는 논문 3편 이상이 필요하다. 기본 목록에는 최대 30편을 표시하며, 별도의 검색 결과 전체 추천 버튼은 두지 않는다. 결과는 근거가 충분한 3~5편만 자동 선택하고 부족하거나 검증에 실패하면 기존 선택을 유지한다. 입력 크기 한도를 넘으면 줄여서 다시 선택하도록 안내한다.

결과 가져오기는 기본적으로 닫혀 있으며 사용자가 필요할 때 직접 연다. Gemini 추천 실행 시 닫고, 성공하면 작업 패널을 2단계 원문 확보로 이동한다. 비어 있는 최신 정리본이나 추천 결과 카드를 1·2단계 사이에 표시하지 않는다. 실제 상세 정리는 원문 확보와 프롬프트 뒤에 표시하고, 저장된 정리 기록은 설정에서 확인할 수 있다. 이 결정은 아래의 기존 30편 상한 및 화면 배치보다 우선한다.

## 2026-10-28 선택적 Gemini 검색어 생성

기본 ‘찾기’는 기존 직접 검색을 유지한다. 별도 ‘AI 검색어 생성’ 버튼은 조사 내용과 선택한 추가 정보만 로컬 서버의 Gemini API로 보내고 영문 검색어 5~8개를 검증해 확인 화면에 표시한다. 사용자가 검색어를 선택해 검색을 실행하며 원래 입력을 조사 기록에 유지한다. 입력 또는 조사가 바뀌면 이전 응답을 적용하지 않는다. 키는 서버 전용이며 공개 Vercel에서는 인증·호출량 보호가 마련되기 전까지 제공하지 않는다. 기존 Gemini 논문 추천 및 상세 정리 흐름은 유지한다.

## 2026-10-28 Gemini API를 통한 1단계 논문 선별

사용자 요청에 따라 로컬 실행에서만 1단계 논문 선별을 Gemini API로 실행할 수 있다. 선택 논문의 제목·초록, 조사 주제, 사용자가 적은 정리 초점만 전달하며 PDF와 후속 상세 정리는 전달하지 않는다. 사용 전 전송 범위와 무료 등급의 데이터 사용을 표시한다. 최대 30편을 전달하고 실제 선택 목록에 있으며 초록이 있는 논문 번호만 검증하여 읽기 순서로 최대 5편 선택한다. 중복·범위 밖 번호 또는 요청 중 변경된 조사·선택은 적용하지 않는다. 추천이 없거나 실패하면 기존 선택을 유지한다.

Gemini 키는 로컬 서버 환경 변수 `GEMINI_API_KEY`에만 둔다. 공개 Vercel은 인증·호출량 보호가 마련되기 전까지 자동 선별을 제공하지 않는다. 수동 프롬프트 복사·결과 가져오기와 상세 정리의 외부 AI 전달은 유지한다. API의 무료 한도와 과금 등급은 사용자 Google 프로젝트 설정을 따른다. 이 결정은 아래 외부 AI 자동 호출 금지 중 1단계 로컬 선별에 우선한다.

## 2026-10-28 폴더 PDF 제목 대조

선택한 조사 폴더의 PDF를 확인할 때 문서 DOI를 우선 대조하고, DOI로 일치하지 않으면 PDF 제목 메타데이터나 첫 페이지에서 일치하는 전체 제목을 찾는다. 고유하게 일치하고 DOI가 충돌하지 않는 경우에만 제목 기준으로 연결해 원문 확보 상태를 표시한다. 중복 제목과 충돌은 직접 확인한다. 파일명이나 참고문헌의 제목은 근거로 사용하지 않는다.

## 2026-10-28 AI 대화에서 연구 이어가기

연구 맥락의 기본 사용처는 사용자가 계속 이용하는 외부 AI 대화다. 새 논문 프롬프트와 PDF를 같은 대화에 전달해, AI가 실제 접근 가능한 이전 논의와 새 자료를 연결하도록 요청한다. 모델이 모든 과거 자료를 영구적으로 기억하거나 스스로 재학습한다고 표현하지 않는다. 이전 자료의 확인 가능 범위와 현재·이전 논문 번호를 구분한다.

새 AI 대화나 다른 모델로 옮길 때는 기존 대화의 AI가 확인 가능한 연구 맥락 노트를 만들어 주도록 요청하는 복사 기능을 제공한다. 사용자가 AI 답변과 필요한 원문을 새 대화에 직접 전달한다. 온닷에 저장한 상세 정리를 포함한 기존 지식 지도 파일은 선택적 보조 수단으로 유지한다. 프롬프트를 만들 때 지도 파일을 자동 다운로드하거나 첨부를 필수로 요구하지 않는다. 이 결정은 아래의 기존 누적 지도 전달 기본값보다 우선한다.

조사 주소에서 새로고침하면 현재 조사와 저장된 선택·메모·작업 초안·주요 작업 화면을 다시 연다. 저장 대기 중인 변경은 같은 탭의 임시 저장본으로 보조 복구하고, 저장 실패 또는 저장소 제한은 성공으로 표시하지 않는다. 브라우저가 파일 선택·폴더 권한을 복원하지 않으며, 새로고침 중이던 다운로드·검색은 재개하지 않는다. 같은 조사 동시 편집의 충돌 처리는 별도 검증이 필요하다. 이 결정은 이전 ‘새로고침 시 첫 화면’ 결정보다 우선한다.

## 2026-10-28 모델 공통 상세 정리와 누적 지식 지도

상세 정리는 모델명을 강제하지 않는 summary-v4-portable을 사용한다. 자료를 분야 전문 도우미의 후속 대화 맥락으로 활용하도록 지시하되, 결과 본문에 학습 보고서·학습 완료 문단은 출력하지 않는다. 화면에는 지침 포함과 누적 정리 수만 표시한다. 모델 재학습·영구 기억·새 대화의 자동 접근을 주장하지 않는다.

가져온 상세 정리 버전과 논문 제목·DOI 스냅샷으로 지식 지도를 만든다. 1단계 추천은 누적에서 제외한다. 현재 조사의 정리와 사용자가 파일로 불러온 기록을 다음 프롬프트에서 연결하며, 본문은 별도 research-knowledge.md로 전달한다. 생성 시 파일 다운로드를 요청하고 사용자가 AI에 직접 첨부하거나 내용을 복사한다. 새 조사에서는 지도 불러오기를 사용한다. 외부 AI 자동 전송·자동 검색은 하지 않는다.

지식 지도는 원문을 대신하는 근거가 아니다. 현재 P번호와 과거 기록의 고유 K키를 구분하고 조건·상충·자료 범위를 보존한다. 같은 기록은 중복 제거하고 내용이 다른 버전은 보존한다. 가져오기 파일 및 불러온 지도 합계는 2MB까지이며 잘못된 파일은 기존 기록을 변경하지 않는다. 자료가 커질 때 관련 부분 자동 검색·압축은 후속이다. 이 결정은 Gemini 전용 명칭·기본 수신자 결정에 우선한다.

## 2026-10-28 상세 정리의 완성도 기준

상세 정리의 목적은 다른 사람에게 조사 내용을 설명할 수 있는 독립 문서다. 논문별 연구 질문·방법을 택한 이유·조건 및 비교 근거·주요 결과·의미를 연결하고, 논문 간 비교와 자연스러운 종합 설명문을 포함한다. 읽기 순서는 보조 정보다. 5편 기준 4,000~7,000자를 참고하되 근거의 밀도에 따라 조절한다. PDF/텍스트 상세 방식에 공통 적용하며 1단계 분량과 PDF 누락 규칙은 유지한다.


## 2026-10-28 PDF 첨부 누락 안내

상세 정리의 PDF 첨부 방식은 AI 대화에 실제 첨부되어 읽을 수 있고 해당 논문으로 식별된 파일만 준비된 것으로 취급한다. 누락이 있으면 [Pn] 논문명 - 파일 첨부 필요 목록만 출력하도록 지시하고 분석은 보류한다. 모든 파일이 준비되면 정리 시작 요청에 따라 분석한다. 초록 선별과 텍스트 전달 방식에는 이 규칙을 적용하지 않는다.


## 2026-10-28 1단계 가져오기 목적 명시

1단계의 기본 제출은 프롬프트 버전이나 생성 문구 유무에 관계없이 추천을 적용한다. 성공하면 목록도 선택 논문만 표시하고 원문 확보로 이동한다. 선택을 바꾸지 않는 상세 결과 저장은 별도 버튼으로 실행한다. 구버전 summaryCtx의 paperIds도 번호 연결에 사용한다.


## 2026-10-28 1단계 결과 가져오기 → 추천 자동 선택

1단계(shortlist-v1)는 AI에서 결과를 읽고 웹에서는 추천 논문만 선택해 원문 확보로 이동한다. 결과 전체 또는 선택 논문: [P번호] 줄을 가져올 수 있다. 전용 줄이 없으면 번호 목록 제목의 [P#]만 인식하며 본문 인용은 선택하지 않는다. 생성 당시 summaryCtx.paperIds에 대응시켜 추천 순서로 1~5편을 선택한다. 불명확·범위 밖·삭제된 논문은 적용하지 않고 입력과 기존 선택을 보존한다. 원래 결과는 정리본 이력에 저장하되 화면에서는 추천 목록만 표시한다. 다운로드는 사용자가 실행한다. 상세 정리 가져오기는 기존 동작을 유지한다.


## 2026-10-28 1단계 추천 중심 출력

1단계 결과는 연구군 도입 2~3문장, 추천 논문 3~5편과 각 이유 1~2문장, 초록 기준 한계 한 문장으로 제한한다. 용어는 필요한 곳에서 괄호로 최대 3개만 풀이한다. 제목 제외 약 500~800자를 목표로 하며 전체 연구군 표·용어 사전·출처 목록을 요청하지 않는다. 자료 부족 시 수를 억지로 채우지 않는다. 입력의 제목·초록·DOI·[P#]는 보존하며 상세 정리는 기존 방식을 유지한다.


## 2026-10-28 초록 선별 우선

기본 작업 화면 1단계는 제목·초록을 포함하는 프롬프트를 즉시 생성한다. PDF 첨부 설정·원문 보관 여부와 무관하며 첨부나 추가 시작 명령을 요구하지 않는다. 연구군과 핵심 추천 최대 3~5편을 초록 범위에서 잠정 판단한다. 기존 PDF 첨부·본문 발췌 방식은 원문 확보 후 상세 정리에 유지한다. 아래 2026-10-23 기본 첨부 결정은 1단계에 적용하지 않는다. 저장 구조는 유지한다.


## 2026-10-28 사용자 선택 PDF 폴더

기본 화면과 서버 시작 경로에서 PC 연결 수신함을 제거한다. 사용자가 각 PC에서 선택한 폴더 아래 Research Landscape/조사-ID 폴더에 PDF를 저장하며, 폴더 확인은 사용자의 버튼으로 실행한다. PDF 원본을 브라우저 저장소에 복사하지 않는다. PDF 본문 첫 두 쪽의 DOI가 현재 조사 논문 하나와 일치할 때만 자동 연결하며, 그 외는 사용자가 선택한다. 브라우저 폴더 권한은 현재 탭에서만 유지하고 다시 선택하도록 한다. 폴더 미선택·저장 실패 시 브라우저 다운로드를 요청한다. 기존 수신함 코드는 보존하지만 기본 실행 경로에서 사용하지 않는다.

## 2026-10-28 PDF 직접 다운로드

새로 받은 PDF는 브라우저 내부 저장소를 거치지 않고 브라우저 다운로드를 요청한다. 여러 건은 브라우저가 추가 다운로드를 차단할 수 있으며 웹페이지는 실제 파일 저장 완료를 확인할 수 없다. 이전에 브라우저에 보관한 PDF는 삭제하지 않고 별도 다운로드할 수 있다. 원문에서 추출한 텍스트와 조사 정보는 기존 브라우저 저장소에 남는다. 직접 받기 요청은 로컬 서버의 프로젝트 폴더에 PDF를 중복 저장하지 않는다. 이 결정은 아래 기존 PDF 보관 방식에 우선한다.

## 2026-10-27 기본 작업 화면 통합

첨부 HTML의 가상 API와 저장소 대체 코드는 가져오지 않는다. 실제 검색과 기존 IndexedDB 저장소를 유지한다. 예시는 사용 안내에서 명시적으로 선택하며 항상 가상 자료임을 표시한다. 검색 연결 실패를 예시 성공으로 대체하지 않는다. 기존 저장한 조사와 예시는 삭제하지 않는다.

## 목적과 사용자

교수님 말씀과 개인 연구 메모에서 조사 질문을 준비하고, 여러 검색식으로 논문을 모아 읽을 순서·비교·근거·랩미팅 자료를 정리하는 개인 연구 도구다. 공개 판매·다중 사용자 서비스로 개발하지 않는다.

전공을 제한하지 않는다. 기존 EUV PR·ALD·HBM 가상 예시를 유지하되 고분자·소재·화학 등에도 같은 조사 구조를 적용한다. 특정 분야의 공정 항목을 강제하지 않으며 자료가 부족하면 미확인으로 남긴다.

## 유지하는 뼈대

- 기존 HTML/CSS/JavaScript ES modules와 Node.js·Express, 같은 출처의 UI/API를 유지한다.
- 탐색과 랩미팅 준비 두 화면, 연구실·검색식·근거 보조 패널, 저장한 조사를 유지한다.
- 기존 선택·메모·비교·Claim·근거·버전·Markdown 내보내기와 디자인 토큰을 재사용한다.
- 사용자 변경·저장 데이터·개인 .env를 임의 삭제하거나 reset하지 않는다. 자동 커밋하지 않는다.
- research-landscape-prompts/ 원본은 수정하지 않는다.

## AI와 외부 작업

- 사이트는 OpenAI·Gemini 등 모델 API를 호출하지 않는다. 무료 API도 기본 의존성에 넣지 않는다. 기존 키가 있어도 개인 핵심 흐름에서 자동 호출하지 않는다.
- 일반 코드가 목적별 프롬프트와 입력 자료를 미리 작성한다. 사용자가 확인·편집·복사해 외부 AI에서 실행하고 결과를 가져온다.
- 지원 목적은 상담·검색식 생성, 검색어 보완, 논문 관련성 검토·독해, 방향·연구실 연결, 비교, 랩미팅 초안, 피드백 반영이다. 후속 미구현 목적은 완료로 표시하지 않는다.
- 첫 상담에 잠정 주제·영문 핵심 키워드·검색식 5~8개를 요청한다. 확인 질문·가정을 남기되 주제 선택 대기로 검색식을 비우지 않는다. 해석할 대상이 전혀 없으면 이유를 표시한다.
- 빈 필수 필드·형식 오류는 원문과 이전 결과를 보존한 보완 요청으로 복구한다. 외부 AI 결과의 스키마·ID·자료 버전을 검증하고 사용자 확인 후 적용한다.
- 외부 AI 로그인·세션·쿠키·브라우저 자동조작으로 모델 API를 대신하지 않는다. 직접 입력·수동 정리는 항상 가능해야 한다.

## 검색·정렬

- OpenAlex 주 검색, Crossref 결측 보완·장애 대체를 유지한다. Semantic Scholar 의존을 다시 넣지 않는다.
- 검색식 최대 8개, 기본 최대 2개 동시 작업이며 실제 공급자 제한에 맞춰 더 낮출 수 있다. 수집·실패·0건·대체 출처를 구분한다.
- DOI·공급자 ID 중복 제거, 발견 검색식·필드 출처 보존, rule-v1 기본 관련성 정렬을 유지한다. 의미 분석·논문 품질 점수로 표현하지 않는다.
- 검색 API에는 확인한 검색식·필터만 전달하고 교수님 원문·연구실 메모를 통째로 보내지 않는다. 키·이메일은 서버에서 관리한다.
- 공급자 무료 범위·가입·키·원문 접근 조건은 실제 연결 시 확인한다. 무제한 무료라고 표현하지 않는다.

## 저장과 개인 서버

- IndexedDB와 전체 백업·복원을 기본으로 한다. 계정·Supabase·클라우드 배포는 필수 조건이 아니다.
- 기본 서버는 개인 PC의 127.0.0.1에서 동작한다. 원격 공개는 별도 요청 전 자동으로 열지 않는다.
- 로컬 저장을 계정 보안·클라우드 동기화로 표현하지 않는다. 탭 충돌·저장 실패·손상·구버전·백업 충돌에서 원본을 보존한다.
- 원문은 전용 로컬 저장 영역을 목표로 한다. 기존 30일 자동 만료를 개인 원문에 강제하지 않고 임시 파일 정책과 사용자 삭제를 구분한다.
- 기존 클라우드·AI 코드와 기록은 임의 제거하지 않고 필수 경로와 분리한다.

## 방향·원문 확장

- 방향 카드·비교는 수동 작성 또는 외부 AI 결과 가져오기로 확장한다. 과거 8편 기준으로 개인 초기 메모를 차단하지 않는다. 연결 근거가 적으면 부족 상태를 표시한다.
- 공개 원문 후보·사용자 파일·개인 MCP 어댑터를 분리한다. 링크 발견·파일 확보·텍스트 추출·내용 확인은 서로 다른 상태다.
- 2026-10-22 Sci-Hub DOI 조회·다운로드는 직접 HTTP 어댑터로 구현했다. 2026-10-23부터는 일괄 버튼을 눌렀을 때 공개 원문이 실패한 논문만 Sci-Hub로 한 편씩 이어서 받고, 행을 펼치면 한 편만 따로 받을 수도 있다. 검색 도중에는 호출하지 않는다. 모델 API나 MCP 설치는 필요하지 않다. MCP 프로세스 연동은 구현하지 않았고 직접 연결과 구분한다.
- 수집 PDF와 추출 본문은 브라우저 IndexedDB에 함께 보관한다. 같은 PDF 파일은 개인 PC의 data/inbox-pdfs 아래 날짜-주제 폴더에 저장한다. 자동 가져오기를 켜면 그 폴더에서 직접 넣은 PDF도 지정한 조사에 연결한다. 이 폴더는 정적 공개 경로가 아니다. 원본 PDF 저장 버튼을 제공하며 조사 백업에는 PDF가 들어가지 않는다. 파일 포함 전체 백업은 후속이다.
- MCP·다운로드 실패가 검색·정리를 막지 않게 한다. 모델 API를 MCP 실행의 필수 경로로 두지 않는다.
- URL·DNS·리다이렉트·경로·형식·크기·시간을 검사하고 원문을 정적 공개 경로에 저장하지 않는다. 재배포 권한을 링크나 소프트웨어 라이선스로 확정하지 않는다.

## 신뢰성과 제외 범위

- 실제 논문·DOI·수치·원문 위치를 지어내지 않는다. 초록만 있으면 본문 페이지·그림 위치를 만들지 않는다.
- 형식 검증, 외부 AI 해석, 원문 확보, 사용자 확인을 같은 검증 상태로 합치지 않는다.
- 예시는 example: ID와 “가상 예시 · 실제 논문 아님” 표시를 유지한다. 사용자 제공 자료는 출처를 구분하고 실제 검색 실패를 예시로 바꾸지 않는다.
- 수치 비교는 단위·조건·근거를 보존한다. 수정 후 Claim의 사용자 확인을 해제한다.
- 가격·결제·구독·상품 FAQ·유료 잠금, 연구 공백·신규성·수주 보장, 적합도·준비도 점수, 일정 관리·자동 PPT 디자인은 범위 밖이다.
