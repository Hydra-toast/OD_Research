# 추가 개발 프롬프트: 유료 AI API 없이 개인 AI 상담 결과 활용

> 최신 기준은 [개인 연구 도구 PRD v2.0](../../.cursor/Research-Landscape-PRD.md)입니다. 본 추가 프롬프트보다 우선하며 상담 이후 목적별 입력 준비·로컬 백업·원문 보관도 PRD를 따릅니다.

이 문서는 `2026-10-21-grok-research-workflow.md`에 대한 변경 지시입니다. 두 문서가 충돌하면 이 문서를 우선 적용하세요. 기존 프롬프트의 다중 검색·결과 통합·출처 보존·저장·원문 처리 요구는 유지하되, 서비스 내부의 유료 AI 호출 요구는 아래 내용으로 대체하세요.

## 1. 확정 방향

사용자는 이미 이용 중인 ChatGPT·Claude·Gemini 등에서 직접 상담하고 결과를 사이트에 붙여 넣습니다. 사이트는 OpenAI 등 유료 AI API를 호출하지 않습니다. 개인 AI 서비스의 이용 조건·사용량 제한은 해당 서비스에 따르며, 서비스 전체를 무제한 무료라고 표현하지 마세요.

사이트의 가치는 여러 검색식을 실행하고 결과를 통합·중복 제거·정렬하며, 자료와 조사 이력을 보존하는 데 있습니다.

변경 흐름:

교수님 말씀·알려진 조건 입력 → 상담용 프롬프트 복사 → 개인 AI에서 상담·검색식 생성 → 결과 붙여넣기 → 사이트에서 확인·수정 → 다중 검색 → 중복 제거 → 규칙 기반 관련성 정렬 → 선택·정리·저장·내보내기

외부 AI 사용은 강제하지 않습니다. 사용자가 조사 기준과 검색식을 직접 입력해 같은 검색 흐름을 실행할 수 있어야 합니다. 외부 AI 계정 로그인·세션·쿠키·브라우저 자동조작을 통해 API를 대신 호출하는 기능은 만들지 마세요.

## 2. 이전 프롬프트에서 대체할 항목

- 3~4절의 발언 해석·주제 제안·범위 상담: 개인 AI에서 수행하고 사이트는 프롬프트 생성·결과 가져오기·수정 기능을 제공합니다.
- 5절의 검색식 생성: 개인 AI에서 생성하거나 사용자가 직접 작성합니다. 사이트는 검증·편집·실행을 담당합니다.
- 7절의 AI 관련성 평가: 기본은 아래 규칙 기반 정렬로 대체합니다. 외부 AI 평가 결과 가져오기는 선택 기능입니다.
- 8절의 Responses API 연결·단가 확인·AI 비용 정산: 이번 구현에서 제외합니다. API 키·결제 등록 없이 핵심 흐름을 사용할 수 있게 하세요.
- 11절의 구현 순서와 12절의 검증 항목도 이 변경에 맞추세요.
- 9절의 Sci-Hub MCP 연동 범위는 유지합니다. MCP 호출과 OpenAI 호출은 별개입니다. MCP를 일반 서버 코드에서 직접 호출하고 AI 모델을 중간에 두지 마세요.

기존 AI 관련 코드와 개인 .env는 무조건 삭제하지 마세요. 현재 변경 흐름에서 유료 호출 경로를 분리·비활성화하고, 이미 설정된 키가 있어도 자동으로 호출되지 않게 하세요. 기존 연구 자료·선택·메모는 보존하세요.

## 3. 첫 화면과 상담 프롬프트

입력 제목은 “교수님이 어떤 말씀을 하셨나요?”를 유지합니다. 입력 내용과 선택 조건으로 일반 코드가 복사 가능한 상담 프롬프트를 구성하세요. 이 작업에 AI를 호출하지 마세요.

주요 버튼:

- 내 AI에서 상담할 프롬프트 복사
- 상담 결과 붙여넣기
- 직접 검색식 작성

복사 전에 전달 내용을 미리 보여주고 사용자가 수정할 수 있게 하세요. 클릭만으로 발언·연구실 정보를 외부 서비스에 자동 전송하지 마세요.

상담 프롬프트는 개인 AI에게 다음을 요청합니다.

1. 교수님 발언, 사용자 조건, AI 추정을 구분하고 근거 문장을 보존할 것
2. 첫 응답부터 초기 검색 계획을 제공할 것. 확인 질문 1~2개는 unknowns에 남기되 답변을 기다리며 검색식을 비우지 말 것
3. 장비·교수님 의도·신규성·연구 공백·실행 가능성을 지어내지 말 것
4. 주제 후보 2~3개를 제안할 것. 미선택 상태라면 발언에 직접적인 넓은 초기 주제를 selectedTopic에 채우고 assumptions에 사용자 확인 전 잠정 제안이라고 명시할 것
5. 잠정 기준이라도 서로 다른 관점의 영문 검색식 5~8개를 첫 응답에 작성할 것. 약어 해석은 assumptions에 표시하고 미확인 장비·특정 재료·수치를 필수 조건으로 추가하지 말 것. 전혀 해석할 연구 대상이 없을 때만 이유와 함께 검색 불가로 남길 것
6. 검색식별 목적과 핵심·선호·제외 키워드를 정리할 것
7. 사이트가 지원한다고 안내한 검색 문법만 사용할 것
8. 첫 결과부터 완전한 JSON으로 출력할 것. selectedTopic의 이름·질문, searchCriteria.core, queries를 채울 것. evidence는 발언의 부분 문자열만 사용하고 접두사를 추가하지 말 것. 전공과 기타 조건을 따로 기록하고 미입력을 조건 없음으로 확정하지 말 것

프롬프트의 JSON 형식과 실제 파서는 같은 버전을 사용하세요. 사용자 입력을 명령어로 실행하지 마세요.

형식이 올바른 JSON이어도 검색식·핵심 키워드·주제가 비었으면 원래 말씀·이전 JSON·누락 항목을 포함한 보완 요청과 복사 버튼을 제공하세요. 이전 1~4개 검색식은 경고 후 허용하되 새 상담 출력은 5~8개를 요청하세요. 검색식의 영문 여부·중복 ID·공백 정규화 중복·지원하지 않는 연산자를 확인하세요. 실행 전에 가정·미확인 조건을 보여주세요.

## 4. 가져올 데이터와 검증

가져오기 형식에는 최소한 다음 필드를 두세요.

- schemaVersion
- professorRequirements: 명시 요구와 입력 근거
- userConditions: 사용자 제공 조건
- assumptions: AI가 추가한 가정
- unknowns: 미확인 조건
- topicCandidates: 주제명·연구 질문·추천 이유
- selectedTopic: 사용자가 선택할 조사 주제
- searchCriteria: 핵심·선호·제외 키워드와 동의어 묶음
- queries: id·영문 검색식·검색 목적

JSON 파싱·형식 검증은 일반 코드로 하세요. Markdown 코드 블록으로 감싼 JSON도 처리하되 eval이나 코드 실행을 사용하지 마세요. 입력 크기·검색식 개수·각 필드 길이를 제한하고 중복·빈 검색식을 확인하세요.

일반 문장으로 붙여 넣은 경우 AI 자동 변환을 시도하지 말고 원문을 보존하면서 필드별 수정 폼과 올바른 형식 재요청 프롬프트를 제공하세요. 오류 위치와 수정 방법을 설명하세요.

가져온 발언 근거가 실제 입력에 있는지 확인하고, 맞지 않으면 사용자 확인 필요로 표시하세요. 형식 검증 통과를 내용의 진실성 검증으로 표현하지 마세요. 원래 발언은 덮어쓰지 마세요. 사용자가 내용과 검색식을 확인한 뒤 검색을 실행하세요.

## 5. AI 없이 관련성 정렬

제목·초록·확정 검색 기준을 바탕으로 코드가 재현 가능한 점수를 계산하세요. 기본은 검색 목적에 대한 키워드 기반 관련성 정렬입니다. AI 의미 분석 결과라고 표현하지 마세요.

다음 요소의 가중치를 명시적으로 정의하고 문서화하세요.

- 핵심 개념·동의어 묶음의 일치 여부와 충족 개수
- 제목 일치에 대한 가중치
- 초록에서 목표·재료·방법·공정 키워드 일치
- 사용자가 명시한 선호·제외 조건
- 여러 독립 검색 관점에서 발견된 사실에 대한 제한된 보조 가중치

최신성·인용 수는 별도 정렬 옵션으로 제공하세요. 동일 점수의 정렬 순서도 고정하세요. 중복 검색식 때문에 점수가 과도하게 올라가지 않게 하고, 검색식 수가 점수에 주는 영향을 제한하세요.

초록이 없는 논문은 정보 부족을 표시하고 무관하다고 확정하지 마세요. 단순 단어 일치로 실험 조건 충족이나 직접적인 의미 일치를 확정하지 마세요. 자동 제외는 명확한 사용자 지정 규칙에 한정하고 제외 목록과 이유를 확인·복원할 수 있게 하세요.

결과에는 템플릿으로 “제목에 핵심 키워드 2개 일치”, “초록에서 공정 키워드 확인”, “서로 다른 검색식 3개에서 발견”, “초록 없음: 관련성 판단 제한”처럼 실제 계산 근거를 표시하세요. 근거 없는 자연어 추천 이유를 생성하지 마세요.

## 6. 선택 기능: 개인 AI로 결과 재검토

기본 검색 흐름의 필수 단계가 아닙니다. 사용자가 선택한 논문의 ID·제목·초록·출처와 조사 기준을 상담용 묶음으로 복사하고 개인 AI에서 검토할 수 있게 하세요. 길면 번호가 있는 묶음으로 나누고 누락 범위를 표시하세요.

반환 형식은 논문 ID·관련성 판단·추천 이유·일치 및 미확인 조건·검토 자료 범위를 포함해야 합니다. 서버나 브라우저에서 AI를 호출하지 마세요.

붙여 넣은 결과의 ID가 실제 논문에 존재하는지 검증하고 중복·누락·없는 ID를 표시하세요. 자료 버전·조사 기준이 바뀌었으면 재확인이 필요하다고 안내하세요. 개인 AI에서 가져온 평가를 규칙 기반 점수와 별도 필드로 저장하고, 사용자 적용 전에는 기존 순서를 바꾸지 마세요.

“외부 AI 평가 · 사용자 가져오기 · 정확성 미검증”을 표시하세요. 원문을 주지 않은 경우 본문 위치·실험 수치를 확인된 근거로 채택하지 마세요. AI가 붙여 넣은 지시·HTML·스크립트를 실행하지 마세요.

## 7. 원문·저장·문서

Sci-Hub MCP 연동 및 원문 처리의 기존 안전·출처·검증 요구는 유지합니다. PDF 확보·텍스트 추출에 OpenAI API는 필요하지 않습니다. 추출한 본문의 외부 AI 전달은 사용자가 내용을 확인하고 직접 복사할 때만 수행하세요. 자동 분석은 하지 마세요.

AI 결과의 출처는 사용자 가져오기로 기록하고 원본 텍스트·확인 상태·가져온 시점·자료 버전을 보존하세요. 사용자가 모델명을 제공한 경우에만 기록하고 추정하지 마세요. 규칙 기반 정렬에는 기준·가중치 버전을 보존하세요. 기존 저장 데이터와 호환되게 확장하세요.

기존 PRD 원본과 제품 계약·결정 문서에 “핵심 사용자 흐름에 유료 AI API를 사용하지 않음”을 우선 결정으로 반영하세요. 이전 OpenAI 요구가 역사적 기록인지 선택적인 후속 기능인지 명확하게 구분하세요. 예전 기록을 현재 완료 상태로 고쳐 쓰지 마세요.

## 8. 검증·완료 기준

- API 키 없이 상담 프롬프트 생성·결과 입력·다중 검색·정렬·저장 가능
- 기존 키가 있어도 이번 사용자 흐름에서 OpenAI 등 유료 AI API로 전송하지 않음
- 정상 JSON·코드 블록·형식 오류·누락·초과 입력 처리
- 상담 없이 검색식 직접 작성 가능
- 동의어·제목/초록 일치·초록 없음·제외 조건·동점 정렬의 실제 의미 있는 검사
- 외부 AI 결과의 없는 ID·중복·누락·오래된 버전 처리
- 여러 검색식의 중복 제거·부분 실패·전체 실패·0건 처리
- 기존 저장 복원과 새 조사 재접속 복원
- 예시 자료·실검색·규칙 기반 정렬·외부 AI 평가의 명확한 구분
- MCP·파일 관련 검사는 원래 프롬프트 기준 유지

고정 응답 검사와 실연동을 구분하고 실행하지 않은 검증을 완료로 보고하지 마세요. 단계 종료 시 docs/PROGRESS.md를 갱신하세요. 변경 파일, 실제 작동 범위, 검사 결과, 남은 작업을 보고하세요.
