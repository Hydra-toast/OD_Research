# Grok 구현 지시서: 직접 다운로드한 PDF 자동 가져오기

## 작업 목표

Research Landscape 프로젝트(C:\Users\USER\Dev\Research_Page)에 다음 흐름을 실제로 구현하고 검증하라.

사용자가 Sci-Hub 등에서 로봇 확인을 직접 처리하고 PDF를 지정 폴더에 저장하면, 로컬 서버가 다운로드 완료를 감지한다. 웹페이지는 해당 PDF를 조사 논문에 연결하고 기존 PDF 보관·본문 추출·분석 프롬프트 흐름에 자동 반영한다.

이번 목표는 로컬 파일 자동 가져오기다. CAPTCHA 자동 풀이, 브라우저 쿠키 추출, 로그인 자동화, 추가 논문 다운로드는 구현 범위에 포함하지 않는다. 구현 계획만 설명하지 말고 코드 수정·검증·문서 기록까지 완료하라.

## 시작 전 확인

- AGENTS.md 및 docs/PRODUCT_CONTRACT.md, PROGRESS.md, DECISIONS.md, TEST_MATRIX.md, BACKLOG.md와 현재 PRD를 읽어라.
- 기존 변경을 확인하고 보존하라. reset·자동 커밋을 하지 말고 research-landscape-prompts/ 원본은 수정하지 마라.
- 2026-10-23 확인 시점에는 Node/Express 로컬 서버, 브라우저 IndexedDB, pdfjs 본문 추출을 사용한다. 검색 공급자는 OpenAlex/Crossref다. 모델 API를 추가할 필요가 없다.
- 현재 코드에는 server/fulltext.js의 extractPdfText, findDoi, pdfFileName, /api/fulltext/upload, src/controller/research.js의 uploadFiles/storeResult, src/repository/idb.js의 saveFulltext/loadFulltextPdf가 있다. 실제 최신 시그니처를 확인하고 재사용하라.
- 브라우저 보관 한도는 PDF_KEEP 기준 파일당 20MB, 조사당 30개/600MB다. 서버 보관 한도와 차이가 있을 수 있으므로 상수를 각각 확인하라.
- 최근 구현으로 성공한 PDF를 프로젝트 data/pdfs에도 보관한다. 이 출력 폴더를 수신 폴더로 감시하면 자기 파일을 다시 가져오는 루프가 생기므로 분리하라.

## 사용자 경험

1. 원문 받기 영역에 ‘다운로드 폴더에서 자동 가져오기’ 켜기/끄기와 수신 폴더 절대 경로·경로 복사를 제공한다. 기본은 꺼짐이다.
2. 기본 수신 폴더는 프로젝트 data/inbox-pdfs로 한다. 켤 때 폴더를 만들고 ‘브라우저에서 이 폴더에 PDF를 저장하세요’라고 안내한다. 브라우저 다운로드 설정이나 사용자 Downloads 전체를 임의 변경·감시하지 마라.
3. 웹페이지에서 조사 하나를 자동 연결 대상으로 명시적으로 지정한다. ‘현재 조사에 연결’ 동작으로 대상 projectId를 고정하고, 화면 전환만으로 다른 조사에 바뀌지 않게 한다.
4. 완료 PDF를 감지하면 감지됨 → 검사·추출 중 → 자동 연결됨 또는 연결 확인 필요 → 저장 완료 상태를 표시한다. 서버 감지만으로 ‘원문 확보’라고 표시하지 마라.
5. DOI가 확실히 일치하면 자동으로 연결한다. 애매하면 파일명과 판단 근거, 조사 논문 선택란을 보여주고 한 번만 사용자 선택을 받는다. 새 논문이나 DOI를 지어내지 마라.
6. 같은 조사에서 정상 원문이 이미 보관돼 있으면 자동 덮어쓰지 않는다. 다른 PDF는 교체 후보로 남겨 확인받는다.
7. 브라우저가 닫혀 있으면 서버가 대기열만 유지한다. 다음에 사이트를 열었을 때 대기 개수를 알리고 대상 조사를 명시적으로 연 뒤 처리한다. 기존 ‘새로고침 시 조사를 자동으로 열지 않음’ 정책을 유지한다.
8. 서버가 꺼져 있던 동안 들어온 파일은 다시 켰을 때 스캔한다. 폴더 감시·로컬 서버가 실행 중이어야 한다는 상태 안내를 제공한다.

## 파일 감지·대기열

- Node 로컬 서버가 지정 수신 폴더의 바로 아래 PDF만 읽는다. 임의 재귀 탐색은 하지 않는다. OS 이벤트만 믿지 말고 시작 시 스캔과 주기적 재확인을 병행하라.
- .crdownload, .part, .tmp 등 다운로드 중간 파일, 0바이트, PDF 이외 파일은 가져오지 않는다.
- 서로 떨어진 여러 검사에서 크기·수정 시간이 안정된 파일을 후보로 삼는다. 안정 상태만으로 완료를 보장하지 말고 읽기 전후 stat 비교, PDF 서명·파싱까지 확인한다. 잠긴 파일이나 읽는 중 바뀐 파일은 제한된 재시도 후 대기 상태로 남긴다.
- 파일명은 신뢰하지 않는다. %PDF- 서명, 최대 크기, 기존 추출 제한·오류 처리를 재사용한다. 큰 파일은 전체 메모리에 올리기 전에 거절한다.
- 한 번에 한 파일씩 처리하고 폭주·무한 재시도를 막는다. 손상·암호화·스캔 PDF는 구분한다. OCR은 이번 범위가 아니다.
- SHA-256으로 파일을 식별한다. 이름을 바꾼 동일 PDF도 중복 처리하지 않는다. 연결 중복 키는 projectId + paperId + sha256으로 잡고 다른 조사에서 같은 PDF를 사용하는 것은 허용한다.
- 대기열은 서버 재시작 후 복원되는 로컬 저장으로 구현한다. 항목 ID, SHA-256, 파일명, 크기, 발견 시각, 상태, 시도 횟수, 오류, 연결 대상, 처리 완료 기록을 보존한다. 원자적 기록을 사용하고 손상 시 원본 PDF와 기존 대기열을 덮어쓰지 마라.
- 원본 파일을 이동·삭제하지 않는다. 명시적으로 제외한 파일은 다시 스캔해도 재등장하지 않도록 기록한다. 대기열·보관 파일에 개수/용량 제한을 두고 초과하면 조용히 누락하지 말고 알린다.

## DOI 연결 기준

- PDF 메타데이터·첫 페이지의 문서 식별 DOI를 우선 확인한다. 본문 참고문헌에서 처음 발견한 DOI 하나를 해당 PDF의 DOI로 단정하지 마라. 기존 findDoi가 단순 첫 일치 추출이면 그대로 자동 연결의 근거로 쓰지 마라.
- 대소문자, doi.org 접두사, 명확한 인용 끝 구두점 등을 정규화하되 DOI의 실제 문자를 잘라내지 않도록 검사하라.
- 문서 자체 DOI가 단일하게 확인되고 대상 조사에서 고유하게 일치할 때만 자동 연결한다.
- 복수 DOI·문서 DOI와 제목 충돌·미일치·스캔본·DOI 미확인은 사용자 연결 확인으로 보낸다. 파일명·제목 유사도는 후보 안내용으로만 사용하라.
- 연구주제·논문 선택이 바뀌는 동안 처리 중이더라도 최초 대상 조사를 보존한다. 대상 조사가 삭제됐거나 조회되지 않으면 미연결 대기로 남긴다.

## 서버와 브라우저 연결

- 적합한 예: server/pdf-inbox.js에 감지·대기열·파일 조회를 분리하고 기존 서버 시작/종료 생명주기에 연결한다. 프런트는 대기 목록 조회, 파일 가져오기, 연결, 완료 확인을 담당한다. 실제 파일 구성에 맞게 조정해도 된다.
- API 예시는 GET /api/pdf-inbox, POST /api/pdf-inbox/settings, GET /api/pdf-inbox/:id/pdf, POST /api/pdf-inbox/:id/ack 등이다. 이 이름 자체보다 동작·검증을 우선한다.
- 브라우저는 프로젝트가 활성화됐을 때만 필요한 파일을 가져온다. 기존 saveFulltext와 조사 메타데이터 저장이 모두 성공한 뒤 서버에 처리 완료를 알린다.
- 저장 실패·브라우저 용량 초과·탭 종료·응답 유실 시 대기 항목은 재처리 가능해야 한다. PDF 저장은 성공했지만 ack가 실패한 경우 재시도해도 중복 저장·중복 완료 알림이 없어야 한다.
- 여러 탭이 열렸을 때 한 항목을 동시에 적용하지 않도록 짧은 처리 임대나 동등한 원자적 잠금과 만료 복구를 구현하라.
- IndexedDB는 서버에서 직접 쓸 수 없다. 서버 보관 성공과 브라우저 보관 성공을 각각 관리하고 완료 기준을 섞지 마라.
- 출처는 ‘로컬 폴더에서 가져온 PDF’로 기록한다. Sci-Hub 다운로드 성공이라고 추정해서 기록하지 마라. 실제 페이지 텍스트·해시·원문 상태가 기존 프롬프트에 들어가도록 연결한다.
- 원문 파일 저장 경로를 자동 공개하지 마라. 클라이언트에는 임의 절대 경로 대신 서버 발급 항목 ID로 파일을 요청하게 한다. 경로 이탈·심볼릭 링크/정션 이탈을 검사하고 기존 Host/Origin 검사를 재사용한다. 폴더 설정·ack 등 변경 요청에는 같은 출처 검사를 적용한다.
- 서버는 기존처럼 루프백에서 실행한다. 토큰·쿠키·개인 파일 내용을 로그에 출력하지 않는다. 수신 파일·대기열은 Git과 정적 제공 대상에서 제외한다.

## 검증과 완료 조건

실제 논문 다운로드 없이 임시 폴더와 테스트용 PDF로 다음을 검증하라. 가상 자료는 example: ID와 ‘가상 예시 · 실제 논문 아님’을 표시한다.

1. 다운로드 중간 파일을 무시하고 완성된 PDF만 처리한다. 쓰기 중 크기가 바뀌면 기다린다.
2. 문서 DOI 고유 일치 → 정확한 조사 논문 연결 → PDF/본문 저장 → 원문 확보 표시 → 프롬프트에 실제 발췌 포함까지 이어진다.
3. 참고문헌 DOI만 존재하거나 복수 후보면 자동 연결하지 않는다.
4. DOI 없음·스캔본·미일치는 사용자 선택으로 연결할 수 있다.
5. 같은 PDF 재발견·이름 변경·서버 재시작·ack 실패 재시도에서 중복 저장하지 않는다.
6. 브라우저 종료 중 발견된 파일은 대기하고, 사이트를 다시 열어 대상 조사를 열면 이어진다.
7. 다른 조사로 전환하거나 대상 조사를 삭제해도 엉뚱한 조사에 적용되지 않는다.
8. 용량 초과·손상·잠금·저장 실패 시 기존 정상 자료와 원본 파일을 보존한다.
9. 다중 탭 중복 처리·임대 만료·비활성화·폴더 누락·경로 이탈·교차 출처 요청을 처리한다.
10. data/pdfs에 생성한 보관 파일이 수신 대기열로 재유입되지 않는다.

checkJs와 필요한 단위·통합 검사, 고정 자료를 사용한 실제 브라우저 흐름 검사를 수행한다. 실사용자 Sci-Hub 로그인·다운로드는 실행하지 않는다. 수행하지 못한 검사는 실패 원인과 함께 미검증으로 남긴다.

완료 후 docs/PROGRESS.md와 TEST_MATRIX.md, 필요한 PRD·결정 기록을 갱신하라. 최종 보고에는 변경 파일, 실제 동작, 검증 결과, 사용자 저장 폴더 경로와 시작 방법, 남은 제약을 간결하게 적어라. 자동 CAPTCHA 해결이나 전체 자동 다운로드를 구현했다고 표현하지 마라.
