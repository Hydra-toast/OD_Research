## 사용 방법

수정된 서버를 시작하거나 기존 서버를 재시작하고 화면을 새로고침한다. 실제 논문 카드에서 **Sci-Hub 원문 받기**를 누른다. 성공하면 **보관 PDF 저장**이 나타나며 선택 논문의 총정리 프롬프트에도 추출 본문이 포함된다. Sci-Hub는 자동 일괄 수집하지 않는다.

## 검사 범위

- 코드 검사 및 전체 단위 검사 171개 통과. 마지막 저장/삭제 보완 후 관련 32개 재검사 통과.
- 고정 응답 화면 검사 1개: PDF/본문 보관, 재열기, 실패 시 기존 데이터 보존, 파일 수 제한, 조사 삭제 시 파일 정리.
- 실제 원문 화면 검사 1개: 실제 Sci-Hub 응답을 앱의 서버·화면·저장소·프롬프트 경로로 확인.
- 검색은 해당 논문의 고정 서지정보를 사용했다. 검색 품질이나 최신 논문 수집률은 검사하지 않았다.

## 남은 제한

- 자동화 Chrome에서 **보관 PDF 저장**은 다운로드 이벤트 이후 `canceled`였다. 앱과 무관한 텍스트 파일 다운로드도 같은 현상이었다. 일반 사용자 브라우저에서 OS 파일 저장 완료는 아직 검증하지 못했다. 저장된 Blob의 바이트·해시·재열기는 확인했다.
- PDF는 브라우저 로컬 저장소에 보관된다. 사이트 데이터 삭제 시 없어지며 조사 JSON 백업에는 PDF가 포함되지 않는다. 서버 영구 파일 저장 및 원본 포함 전체 백업은 후속이다.
- 로봇 확인·주소 변경·원문 없음은 실패 상태로 남는다. 인증 확인을 자동 우회하지 않는다. 한 편의 성공은 전체 논문 확보율을 보장하지 않는다.
- MCP 프로세스 연동은 수행하지 않았다. 이번 구현은 직접 HTTP 공급자 어댑터다.

## 재현

고정 응답: `node node_modules/@playwright/test/cli.js test --config=playwright.scihub.config.js`

실제 한 편: PowerShell에서 `$env:SCIHUB_LIVE_TEST='1'` 설정 후 같은 명령 실행. 실제 다운로드 요청 1회만 발생하도록 검증하며 자동 재시도는 꺼져 있다.
